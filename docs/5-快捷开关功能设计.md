# 5-快捷开关功能设计

> 本文档定义「快捷开关」功能的完整设计：桌面上的横向开关栏、开关类型、交互逻辑、视觉规范、设置入口。
> 快捷开关独立于桌面组件系统，是桌面上的一个独立区域。

---

## 一、功能概述

快捷开关是桌面上的一个**横向可滚动的开关栏**，放置系统功能开关（WiFi、蓝牙、手电筒等），
用户在桌面上左右键导航、确认键切换开关状态。

### 与桌面组件系统的关系

| 维度 | 桌面组件 | 快捷开关 |
|------|---------|---------|
| 方向 | 垂直列表 | 横向栏 |
| 内容 | 应用、网址、日历、内存、存储、时长 | 系统功能开关（WiFi、蓝牙、锁屏等） |
| 操作 | 上下导航、确认编辑 | 左右导航、确认切换 |
| 设置入口 | 桌面设置 → 桌面组件设置 | 桌面设置 → 快捷开关设置 |
| 数据存储 | `KeydroidxWidgetStorage` | `KeydroidxQuickToggleStorage`（新建） |

## 二、开关类型

共 10 种开关，分三类行为：

### 2.1 双状态开关（开/关）

| 开关 | 图标 | 开状态色 | 关状态色 | 实现方式 | 权限 |
|------|------|---------|---------|---------|------|
| WiFi | `ic_nokia_wifi` | 蓝色 `#4FC3F7` | 灰色 `#444` | `WifiManager.setWifiEnabled` / `isWifiEnabled` | 位置权限（Android 10+） |
| 蓝牙 | `ic_nokia_bluetooth` | 蓝色 `#4FC3F7` | 灰色 `#444` | `BluetoothAdapter.enable/disable` / `state` | 蓝牙权限 |
| 手电筒 | `ic_nokia_torch`（新建） | 黄色 `#FFEB3B` | 灰色 `#444` | API ≥ 23: `CameraManager.setTorchMode`；API < 23: `Camera.open()` + `FLASH_MODE_TORCH` | 相机权限 |
| 静音 | `ic_nokia_mute`（新建） | 红色 `#F44336` | 灰色 `#444` | `AudioManager.setRingerMode(RINGER_MODE_NORMAL/SILENT)` | 无 |

### 2.2 跳转开关（点击跳转系统设置页）

| 开关 | 图标 | 颜色 | 跳转目标 | 说明 |
|------|------|------|---------|------|
| 飞行模式 | `ic_nokia_airplane` | 橙色 `#FF9800` | `Settings.ACTION_AIRPLANE_MODE_SETTINGS` | 普通应用无法直接切换，跳转设置页 |
| 移动数据 | `ic_nokia_data`（新建） | 橙色 `#FF9800` | `Settings.ACTION_DATA_USAGE_SETTINGS` 或 `ACTION_NETWORK_OPERATOR_SETTINGS` | 普通应用无法直接切换，跳转设置页 |
| 热点 | `ic_nokia_hotspot`（新建） | 橙色 `#FF9800` | `Settings.ACTION_TETHERING_SETTINGS` 或 hotspot Intent | 普通应用无法直接切换，跳转设置页 |

### 2.3 动作开关（点击执行一次性动作，无开/关状态）

| 开关 | 图标 | 颜色 | 行为 | 权限 |
|------|------|------|------|------|
| 锁屏 | `ic_nokia_lock` | 白色 `#FFFFFF` | `DevicePolicyManager.lockNow()` | 设备管理员（已有） |
| 音量+ | `ic_nokia_vol_up`（新建） | 白色 `#FFFFFF` | `AudioManager.adjustVolume(STREAM_MUSIC, ADJUST_RAISE)` | 无 |
| 音量- | `ic_nokia_vol_down`（新建） | 白色 `#FFFFFF` | `AudioManager.adjustVolume(STREAM_MUSIC, ADJUST_LOWER)` | 无 |

### 状态指示汇总

| 类别 | 状态指示方式 | 图标颜色 | 方块底色 |
|------|------------|---------|---------|
| 双状态开关-开 | 图标亮色 + 浅色底 | 对应功能色 | `rgba(功能色, 0.18)` |
| 双状态开关-关 | 图标灰色 + 淗色底 | `#444` | `rgba(255,255,255,0.04)` |
| 跳转开关 | 图标橙色 + 浅橙底 | `#FF9800` | `rgba(255,152,0,0.12)` |
| 动作开关 | 图标白色 + 浅底 | `#FFFFFF` | `rgba(255,255,255,0.06)` |
| **选中（光标所在）** | 蓝色高亮框 | 同上 | `rgba(33,150,243,0.4)` + 1px `#2196F3` 边框 |

## 三、桌面显示

### 3.1 位置

**桌面布局调整**：快捷应用栏从顶部移至底部（紧贴软键栏上方），快捷开关栏占据原快捷应用栏的位置（状态栏正下方），桌面组件区域位于中间且**可垂直滚动**。

新布局从上到下：

```
┌─────────────────────────────────────────┐
│ 状态栏（信号/运营商/电量等）               │  ← 不变
├─────────────────────────────────────────┤
│ 快捷开关栏（横向滚动）                    │  ← 新增，占原快捷应用栏位置
├─────────────────────────────────────────┤
│                                         │
│ 桌面组件区域（可垂直滚动）                │  ← 中间，组件多时滚动
│                                         │
├─────────────────────────────────────────┤
│ 快捷应用栏（横向，从顶部移到底部）        │  ← 紧贴软键栏上方
├─────────────────────────────────────────┤
│ 软键栏（左软键/界面名/右软键）            │  ← 不变
└─────────────────────────────────────────┘
```

**布局变更说明**：
- 快捷应用栏从原位置（状态栏下方）移至软键栏正上方，不留间距紧贴
- 快捷开关栏占据快捷应用栏原位置（状态栏正下方）
- 桌面组件区域位于快捷开关栏与快捷应用栏之间，填充中间剩余空间
- 桌面组件区域使用 `ScrollView` 包裹，内容超出时可上下滚动
- 15 项组件上限保留不变

**焦点导航区域顺序（从上到下）**：

| 序号 | 区域 | 方向 |
|------|------|------|
| 1 | 快捷开关栏 | 横向（左/右） |
| 2 | 桌面组件区域 | 纵向（上/下，可滚动） |
| 3 | 快捷应用栏 | 横向（左/右） |

### 3.2 布局规格

| 属性 | 值 | 说明 |
|------|-----|------|
| 高度 | 28dp | 与快捷应用栏同高 |
| 横向滚动 | `HorizontalScrollView` | 内容超出可左右滚动 |
| 每个开关格 | 24dp × 22dp | 固定大小 |
| 间距 | 4dp | 格子之间 |
| 内边距 | 左右 6dp，上下 3dp | |
| 对齐 | 垂直居中 | |

### 3.3 焦点导航

桌面焦点体系更新为三段（从上到下）：

```
快捷开关栏（横向）↕ 桌面组件区域（纵向，可滚动）↕ 快捷应用栏（横向）
```

#### 快捷开关栏焦点导航

| 按键 | 在快捷开关栏中 | 从其他区域进入 |
|------|--------------|--------------|
| 左 | 同行左移一个开关；已到最左 → 不动（不回绕） | — |
| 右 | 同行右移一个开关；已到最右 → 不动（不回绕） | — |
| 上 | 已到最顶 → 不动（不跳到状态栏） | — |
| 下 | 跳到桌面组件区域第一项 | 从快捷应用栏按上 → 快捷开关栏最后一项 |
| 确认键 | 切换/执行/跳转 | — |

#### 桌面组件区域焦点导航（新增滚动逻辑）

| 按键 | 在组件区域中 | 从其他区域进入 |
|------|------------|--------------|
| 上 | 向上滚动一行；已到第一项再按上 → 跳到快捷开关栏最后一项 | 从快捷开关栏按↓ → 组件区域第一项 |
| 下 | 向下滚动一行；已到最后一项再按下 → 跳到快捷应用栏第一项 | 从快捷应用栏按↑ → 组件区域最后一项 |
| 左 | 不动（不跨区域） | — |
| 右 | 不动（不跨区域） | — |
| 确认键 | 编辑当前选中组件 | — |

> **滚动行为说明**：组件区域整行滚动（一次一行，按一下方向键滚一行），非像素级平滑滚动。
> 组件数量不超出显示区域时不可滚动，方向键上下在边缘直接跳转相邻区域。
> 组件数量超出显示区域时，先滚动内容，滚到最边缘再按对应方向键才跳出组件区域。

#### 快捷应用栏焦点导航

| 按键 | 在快捷应用栏中 | 从其他区域进入 |
|------|--------------|--------------|
| 左 | 同行左移一个应用；已到最左 → 不动（不回绕） | — |
| 右 | 同行右移一个应用；已到最右 → 不动（不回绕） | — |
| 上 | 跳到桌面组件区域最后一项 | 从组件区域按↓ → 快捷应用栏第一项 |
| 下 | 不动（已到底部，软键栏不可聚焦） | — |
| 确认键 | 启动当前选中应用 | — |

### 3.4 底部软键

快捷开关栏选中时，底部软键栏显示：

| 软键 | 文字 | 行为 |
|------|------|------|
| 左软键 | 选项 | 进入快捷开关设置页 |
| 右软键 | 返回 | 桌面默认行为（无操作或回桌面） |

> 注意：快捷应用栏移到底部后紧贴软键栏上方，但两者是独立区域，互不干扰。

## 四、设置界面

### 4.1 设计思路

快捷开关的类型固定且有限（10 种），不存在「添加」和「删除」的概念。
设置页固定列出全部 10 种开关，用户通过**勾选/取消勾选**控制哪些开关在桌面显示，
通过**排序**调整显示顺序。

> 不需要 S6（添加-类型选择）和 S3（删除模式），比 1 号文档的组件设置状态机更简单。

### 4.2 设置入口

在桌面设置菜单中新增一项：

```
桌面设置 (KeydroidxDesktopSettingsFragment)
├─ 0  顶部快捷栏设置
├─ 1  壁纸设置
├─ 2  桌面组件设置
├─ 3  快捷开关设置    ← 新增
├─ 4  按键绑定
└─ 5  按键绑定向导
```

### 4.3 S1 正常浏览（勾选列表）

固定列出全部 10 种开关，每行前有勾选框，已启用的打勾：

```
┌──────────────────────────────────┐
│ 快捷开关设置                       │
│ 已启用 6 / 10 项                  │
├──────────────────────────────────┤
│                                  │
│  [✓] 📶  WiFi              [WiFi] │  ← 光标在第一行
│  [✓] 🔵  蓝牙              [蓝牙] │
│  [✓] 🔦  手电筒            [手电筒]│
│  [✓] 🔒  锁屏              [锁屏] │
│  [✓] ✈️  飞行模式          [飞行] │
│  [✓] 🔇  静音              [静音] │
│  [ ] 📶  移动数据          [数据] │
│  [ ] 📡  热点              [热点] │
│  [ ] 🔊  音量+             [音量+]│
│  [ ] 🔉  音量-             [音量-]│
│                                  │
├──────────────────────────────────┤
│ 选项                            返回│
└──────────────────────────────────┘
```

#### 行内容

- 左侧：`[✓]` 或 `[ ]` 勾选框
- 中间：图标 + 开关名称
- 右侧：类型标签（灰色小字，如 `[WiFi]`）

#### 操作

| 按键 | 行为 |
|------|------|
| 上 / 下 | 移动光标，列表滚动跟随 |
| 确认键 | **切换勾选状态**：`[ ]` → `[✓]`（启用），`[✓]` → `[ ]`（禁用） |
| 左软键 | 弹出选项菜单（→ S2） |
| 右软键 | 返回桌面设置 |

> ⚠️ **按键配对规范（DOWN/UP 成对消费）**：S1 左软键弹出 S2 菜单、S4 确认键拎起进入 S5 时，若按键 DOWN 已在 `KeydroidxDesktopActivity.dispatchKeyEvent` 本层被消费（`return true`），须同步消费对应的 UP（含 REPEAT），禁止只消费 DOWN。否则 DOWN 被吞、UP 穿透到新页面可点击 View 时，UP 会合成 `performClick()` 触发第二次动作（例：进入 S2 后又自动选中第一项；进入 S5 后又自动放下）。实现用 `lastHandledDownKeyCode` 记录被本层消费的 keyCode，非 DOWN 分支对相同 keyCode `return true` 吞掉，未消费键 DOWN 路径复位为 `KEYCODE_UNKNOWN`。

#### 勾选即时生效

勾选/取消勾选**即时持久化**，无需额外保存步骤：
- 勾选 → `storage.setEnabled(type, true)` → 桌面开关栏立即新增该开关
- 取消勾选 → `storage.setEnabled(type, false)` → 桌面开关栏立即移除该开关

#### 边界情况

- 全部 10 项都已启用：正常显示，无特殊处理
- 全部 10 项都已禁用：桌面快捷开关栏隐藏（不占位），列表仍可浏览和勾选
- 仅 1 项启用：S2 菜单中「排序」灰掉
- 0 项启用：S2 菜单中「排序」灰掉

### 4.4 S2 选项菜单

只有两项：**排序** / **全选切换**（全不选不可选，见下）

```
┌──────────────────────┐
│ 排序                  │  ← 光标默认在此
│ 全选/全不选          │
└──────────────────────┘
```

| 菜单项 | 行为 | 灰掉条件 |
|--------|------|---------|
| 排序 | 进入排序模式（S4） | 启用项 < 2 时灰掉 |
| 全选/全不选 | 在「全选」和「全不选」间切换 | — |

> 「全选/全不选」根据当前状态动态显示文字：
> - 当前有未勾选项 → 显示「全选」
> - 当前全部已勾选 → 显示「全不选」

> 没有添加、没有删除，因为开关类型固定 10 种。

> ⚠️ **按键处理规范（接入 KeydroidxKeyBinding）**：S2 选项菜单是独立 Window（`Dialog`/`DialogFragment`），弹出后按键事件到达不了 `KeydroidxDesktopActivity`，其 `dispatchKeyEvent` 对菜单无效。菜单的按键处理**必须复用用户自定义的按键映射 `KeydroidxKeyBinding`，禁止写死 keyCode**：在 `onCreate` 中通过 `((KeydroidxDesktopActivity) requireActivity()).getKeyBinding()` 取得真实绑定实例；`setOnKeyListener` 内先 `keyBinding.resolveAction(event)` 解析成语义动作（`ACTION_SOFT_LEFT`/`ACTION_SOFT_RIGHT`/`ACTION_SELECT` 等）再分发；`KEYCODE_BACK` 由菜单单独处理（关闭菜单回到 S1）。不得直接判断 `KEYCODE_SOFT_LEFT` 等具体键码，以免漏掉 `KEYCODE_MENU` 等用户设备实际发出的键码，且需与用户在「按键绑定设置」中的自定义保持一致。

### 4.5 S4/S5 排序模式

仅对**已启用的开关**排序，禁用的开关不参与排序（在排序模式下隐藏）。

## 五、数据模型

### 5.1 数据结构

```java
public class KeydroidxQuickToggleItem {
    private int type;        // 开关类型常量（0~9，固定）
    private boolean enabled; // 是否在桌面显示
    private int sortOrder;   // 排序顺序（仅 enabled=true 的项参与排序）
}
```

> 10 种开关类型固定不变，`type` 范围 0~9。
> `enabled` 控制是否在桌面开关栏显示。
> `sortOrder` 只对已启用项有意义，排序时只重排 enabled=true 的项。

### 5.2 类型常量

```java
public static final int TOGGLE_WIFI = 0;
public static final int TOGGLE_BLUETOOTH = 1;
public static final int TOGGLE_TORCH = 2;
public static final int TOGGLE_MUTE = 3;
public static final int TOGGLE_AIRPLANE = 4;
public static final int TOGGLE_MOBILE_DATA = 5;
public static final int TOGGLE_HOTSPOT = 6;
public static final int TOGGLE_LOCK = 7;
public static final int TOGGLE_VOLUME_UP = 8;
public static final int TOGGLE_VOLUME_DOWN = 9;
```

### 5.3 存储格式

SharedPreferences key: `quick_toggles`

```json
[
  {"type": 0, "enabled": true,  "sortOrder": 0},
  {"type": 1, "enabled": false, "sortOrder": 6},
  {"type": 2, "enabled": true,  "sortOrder": 2},
  {"type": 3, "enabled": true,  "sortOrder": 4},
  {"type": 4, "enabled": true,  "sortOrder": 3},
  {"type": 5, "enabled": false, "sortOrder": 7},
  {"type": 6, "enabled": false, "sortOrder": 8},
  {"type": 7, "enabled": true,  "sortOrder": 1},
  {"type": 8, "enabled": true,  "sortOrder": 5},
  {"type": 9, "enabled": false, "sortOrder": 9}
]
```

> 全部 10 种开关都存储，`enabled` 字段控制是否在桌面显示。
> 桌面加载时只取 `enabled=true` 的项，按 `sortOrder` 排序后构建开关栏。

### 5.4 默认初始配置

| 顺序 | 开关 | 类型常量 | enabled |
|------|------|---------|---------|
| 0 | WiFi | `TOGGLE_WIFI` (0) | ✅ true |
| 1 | 锁屏 | `TOGGLE_LOCK` (7) | ✅ true |
| 2 | 手电筒 | `TOGGLE_TORCH` (2) | ✅ true |
| 3 | 飞行模式 | `TOGGLE_AIRPLANE` (4) | ✅ true |
| 4 | 静音 | `TOGGLE_MUTE` (3) | ✅ true |

### 6.0 矢量图加载规范（API 19 兼容）

> ⚠️ **Android 4.4（API 19）不支持在布局 XML 中用 `android:src` 引用 `<vector>` 矢量图，会抛 `invalid drawable tag vector` 崩溃。**

|------|---------|----------|

| 代码中加载矢量图 | `AppCompatResources.getDrawable(context, R.drawable.ic_nokia_xxx)` | ❌ 同上 |
| 布局根标签 | 必须声明 `xmlns:app="http://schemas.android.com/apk/res-auto"` | ❌ 只声明 `xmlns:android` |
| 图标颜色切换 | `drawable.setColorFilter(color, PorterDuff.Mode.SRC_ATOP)` | ❌ `drawable.setTint(color)`（API 21+） |

> 详见 `安卓 4.4（API 19）矢量图崩溃修复计划.md`。

## 七、手电筒双版本实现

### 7.1 问题背景

`CameraManager.setTorchMode()` 是 Android 6.0（API 23）才引入的 API。
项目 `minSdk=14`，必须兼容 API 14~22 的旧设备。

### 7.2 实现策略

```
Build.VERSION.SDK_INT >= 23
  → 使用 CameraManager.setTorchMode()（新方案，稳定可靠）
Build.VERSION.SDK_INT < 23
  → 使用 Camera.open() + Parameters.FLASH_MODE_TORCH（旧方案，兼容旧设备）
```

### 7.3 新方案（API ≥ 23）

```java
private CameraManager cameraManager;
private String cameraId;
private boolean torchOn = false;

public void initTorch(Context context) {
    if (Build.VERSION.SDK_INT >= 23) {
        cameraManager = (CameraManager) context.getSystemService(Context.CAMERA_SERVICE);
        try {
            // 使用后置闪光灯
            String[] ids = cameraManager.getCameraIdList();
            for (String id : ids) {
                CameraCharacteristics c = cameraManager.getCameraCharacteristics(id);
                if (c.get(CameraCharacteristics.FLASH_INFO_AVAILABLE) != null
                    && c.get(CameraCharacteristics.LENS_FACING) == CameraCharacteristics.LENS_FACING_BACK) {
                    cameraId = id;
                    break;
                }
            }
        } catch (CameraAccessException e) { /* 无法访问相机 */ }
    }
}

public void toggleTorch() {
    if (Build.VERSION.SDK_INT >= 23 && cameraManager != null && cameraId != null) {
        try {
            torchOn = !torchOn;
            cameraManager.setTorchMode(cameraId, torchOn);
        } catch (CameraAccessException e) {
            torchOn = false;
        }
    }
}

public void releaseTorch() {
    if (Build.VERSION.SDK_INT >= 23 && cameraManager != null && cameraId != null) {
        try {
            cameraManager.setTorchMode(cameraId, false);
        } catch (CameraAccessException ignored) {}
    }
}
```

### 7.4 旧方案（API < 23）

```java
private Camera camera;
private boolean torchOn = false;

public void toggleTorch() {
    if (torchOn) {
        turnOff();
    } else {
        turnOn();
    }
}

private void turnOn() {
    try {
        camera = Camera.open();
        Camera.Parameters params = camera.getParameters();
        List<String> supportedFlash = params.getSupportedFlashModes();
        if (supportedFlash != null && supportedFlash.contains(Camera.Parameters.FLASH_MODE_TORCH)) {
            params.setFlashMode(Camera.Parameters.FLASH_MODE_TORCH);
        } else {
            // 设备不支持手电筒
            return;
        }
        camera.setParameters(params);
        camera.startPreview();
        torchOn = true;
    } catch (Exception e) {
        // 相机被占用或权限不足
        torchOn = false;
        if (camera != null) { camera.release(); camera = null; }
    }
}

private void turnOff() {
    try {
        if (camera != null) {
            Camera.Parameters params = camera.getParameters();
            params.setFlashMode(Camera.Parameters.FLASH_MODE_OFF);
            camera.setParameters(params);
            camera.stopPreview();
            camera.release();
        }
    } catch (Exception e) {
        if (camera != null) { camera.release(); }
    } finally {
        camera = null;
        torchOn = false;
    }
}
```

### 7.5 旧方案的已知限制

| 问题 | 说明 | 降级处理 |
|------|------|---------|
| 相机资源独占 | `Camera.open()` 持有硬件资源，其他应用无法使用相机 | 用户在桌面操作手电筒时，无法同时拍照（可接受） |
| 相机被占用时失败 | 如果其他应用正在用相机，`open()` 抛异常 | catch 后 Toast「相机被占用」，恢复关状态 |
| 无外部监听 | 无法感知其他应用改变手电筒状态 | 手动维护 `torchOn` 变量，桌面 onResume 时同步重置为关（旧方案保守策略） |
| 部分设备无手电筒 | `getSupportedFlashModes()` 不返回 `FLASH_MODE_TORCH` | Toast「设备不支持手电筒」，开关保持关态 |
| `Camera` API 已废弃 | Android 5.0 起废弃，但在 < 23 设备上仍正常工作 | 仅在 API < 23 时使用，不受 deprecated 影响 |

### 7.6 统一调用入口

`NokiaQuickToggleHelper` 中统一暴露 `toggleTorch(Context)` 方法，内部按版本分支：

```java
public static void toggleTorch(Context context) {
    if (Build.VERSION.SDK_INT >= 23) {
        // 新方案
        CameraManager cm = (CameraManager) context.getSystemService(Context.CAMERA_SERVICE);
        // ... 见 7.3
    } else {
        // 旧方案
        // ... 见 7.4
    }
}
```

### 7.7 状态监听

| API | 监听方式 |
|-----|---------|
| ≥ 23 | `CameraManager.registerTorchCallback(TorchCallback)` — 可监听外部变化 |
| < 23 | 无外部监听能力，手动维护 `torchOn` 变量 + onResume 时保守重置为关 |

> 旧方案 onResume 重置策略：用户离开桌面期间（打开其他应用），手电筒可能因相机被抢占而关闭，但旧方案无法感知。onResume 时如果 `torchOn=true` 但相机已被其他应用抢占，关掉手电筒并恢复 UI 关态。

### 8.1 实时监听

| 开关 | 监听方式 | 刷新时机 |
|------|---------|---------|

### 8.2 刷新策略

- 桌面 `onResume` 时刷新所有开关状态
- 注册 BroadcastReceiver 实时监听 WiFi/蓝牙/静音/飞行模式变化
- 动作型开关（锁屏/音量±）不刷新状态，执行后图标不变
