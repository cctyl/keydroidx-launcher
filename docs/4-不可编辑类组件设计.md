# 4-不可编辑类组件设计

> 本文档定义四种无可编辑属性的组件类型：日历、内存信息、存储信息、使用时长。
> 它们没有独立的编辑界面，行为由 1 号文档的状态机覆盖，本文档补充其添加、编辑、显示的完整约定。

---

## 一、类型清单

| 类型常量 | 类型名 | 显示内容示例 |
|---------|--------|------------|
| `TYPE_CALENDAR` | 日历 | 今日日期 + 农历 |
| `TYPE_MEMORY` | 内存信息 | RAM 2.1G/4G + 进度条 |
| `TYPE_STORAGE` | 存储信息 | 存储 45G/128G + 进度条 |
| `TYPE_USAGE` | 使用时长 | 今日: 2h 30m |

> 这四种类型的共同点：**无可配置属性**，添加即固化，数据在桌面实时刷新。

---

## 二、添加流程

### 入口

S6 组件类型选择 → 选中其中一种 → **直接添加**，不进入任何编辑页。

### 操作步骤

```
S6 选中「日历」/「内存信息」/「存储信息」/「使用时长」
  │
  ├─ 构造 KeydroidxWidgetItem(type=对应类型, payload=null, label=null)
  ├─ KeydroidxWidgetStorage.addItem(item)
  └─ exitCurrent → 回到 S1
```

- 无 `payload`、无 `label`：这四种类型的数据完全由系统实时获取，不需要存储额外参数
- 添加后立即在 S1 列表中显示，显示内容由组件自身实时计算

### 去重

| 场景 | 处理 |
|------|------|
| 同类型已存在 | **允许重复添加**（例如用户想同时显示两个日历组件在不同位置，虽然没什么意义但不禁止） |
| 达到 15 项上限 | S6 中这些类型不会被灰掉，但 `addItem` 会在 S1 层面被 15 项上限拦截 |

> 设计理由：不额外做去重逻辑，15 项上限已经足够限制。用户如果加了两个内存信息组件，那是用户的选择。

## 三、编辑行为

### S1 确认键

| 类型 | 确认键行为 |
|------|-----------|
| 日历 | Toast「该组件不可编辑」 |
| 内存信息 | Toast「该组件不可编辑」 |
| 存储信息 | Toast「该组件不可编辑」 |
| 使用时长 | Toast「该组件不可编辑」 |

### Toast 交互

```
S1 确认键（光标在不可编辑类型上）
  │
  └─ 弹出 Toast：「该组件不可编辑」
      │
      ├─ Toast 显示期间按任意键（确认/方向键/返回/右软键）→ Toast 消失
      ├─ Toast 超时自动消失（系统默认时长，约 3~4 秒）
      └─ Toast 消失后恢复 S1 正常交互
```

- Toast 不阻塞界面，底层 S1 列表仍可见
- Toast 显示期间不改变焦点位置，Toast 消失后光标停原地
- 不弹 dialog、不开新 Fragment、不改状态

### 不进入编辑模式

这四种类型没有编辑页，确认键不触发任何页面跳转。
用户想调整这些组件的位置或删除它们，通过 S2 菜单的排序/删除功能操作。

## 四、桌面显示

### 显示位置

组件在桌面 `notificationArea` 中的显示位置由 S1 排序决定，与其他类型一致。

### 数据刷新

| 类型 | 数据来源 | 刷新时机 |
|------|---------|---------|
| 日历 | `java.util.Calendar` + 农历计算 | 桌面 `onResume` / 日期变更 |
| 内存信息 | `ActivityManager.MemoryInfo` | 桌面 `onResume` / 定时轮询（如每 30s） |
| 存储信息 | `StatFs` / `StorageManager` | 桌面 `onResume` / 定时轮询 |
| 使用时长 | `UsageStatsManager` | 桌面 `onResume` / 定时轮询 |

> 具体刷新策略属于 `KeydroidxDesktopFragment` 的实现细节，本文档只约束交互行为。

### 显示格式

内存和存储采用**文字 + 条形进度条**的展示方式，使用时长无比例概念，纯文字。

#### 桌面整体视觉规范

以下规范复用项目现有的诺基亚 S40/S60 风格，确保组件区域与桌面整体一致：

| 元素 | 规格 | 参考资源 |
|------|------|---------|
| 桌面背景 | 垂直渐变 `#0d1b3e → #1a3a6b → #0d1b3e`（上→中40%→下） | `bg_keydroidx_desktop.xml` |
| 选中高亮 | 半透明蓝 `#2196F3` + alpha 40%（即 ARGB `#662196F3`），圆角 4dp | `bg_keydroidx_selected.xml` |
| 分割线 | 1dp 高，虚线，白色 15% 透明度，左右 6dp 内缩 | `bg_keydroidx_divider_dashed.xml` |
| 字体 | 优先 `monospace`（等宽），回退 `sans-serif`；字号 11sp；白色 `#FFFFFF`；字间距 0.3 | — |
| 百分比文字 | 9sp，`rgba(255,255,255,0.5)`（即 `#80FFFFFF`），进度条右侧 3dp | — |
| 类型标签 | 7sp，`rgba(255,255,255,0.3)`（即 `#4DFFFFFF`），仅 S1 设置列表中显示 | — |
| 底部软键栏 | 背景 `rgba(0,0,0,0.3)`，顶部 1px 白色 8% 透明度分割线，高 20dp | `bg_keydroidx_softkey.xml` |
| 装饰圆环 | 右下角双圆环，外环 60dp、内环 44dp，`rgba(255,255,255,0.05)`，仅桌面显示 | `deco_rings` |

#### 图标规格

图标不用 emoji，用纯色 vector drawable 或 shape drawable，保持 14~16dp 尺寸，与现有 `ic_keydroidx_*` 系列风格一致：

| 类型 | 图标样式 | 尺寸 | 参考现有资源 |
|------|---------|------|------------|
| 日历 | 白色圆角方块 + 左右上角红色小方块 | 14×12dp | `ic_keydroidx_cal_small.xml` |
| 内存 | 蓝色圆角方块 + 右侧橙色窄条 | 12×10dp | `ic_keydroidx_radio.xml` 风格 |
| 存储 | 灰色圆角方块 + 内部横线 | 12×10dp | 新建 vector |
| 使用时长 | 白色圆环 + 内部指针 | 12×12dp | 新建 vector |

> 图标与文字之间间距 5dp，垂直居中对齐。

> ⚠️ **矢量图加载规范（API 19 兼容）**：以上图标均为 vector drawable。
> - 布局 XML 中引用时必须用 `app:srcCompat`，**不能用 `android:src`**
> - 代码中加载时必须用 `ContextCompat.getDrawable()` 或 `AppCompatResources.getDrawable()`
> - 布局根标签必须声明 `xmlns:app="http://schemas.android.com/apk/res-auto"`
> - 图标颜色切换用 `setColorFilter()`，**不能用 `setTint()`**
> - 详见 `安卓 4.4（API 19）矢量图崩溃修复计划.md`

#### 进度条规格

| 属性 | 值 |
|------|-----|
| 宽度 | 50dp |
| 高度 | 4dp |
| 形状 | 圆角矩形（radius 2dp） |
| 背景轨 | `rgba(255,255,255,0.15)`（白色 15% 透明度，即 `#26FFFFFF`） |
| 内存填充色 | 蓝色 `#4FC3F7` |
| 存储填充色 | 绿色 `#81C784` |
| 填充圆角 | 与背景轨一致（radius 2dp） |
| 百分比文字 | 9sp，`rgba(255,255,255,0.5)`（即 `#80FFFFFF`），进度条右侧 3dp |

> - 进度条用自定义 View 或 `ProgressBar` 实现，圆角矩形 + 纯色填充，无渐变、无动画。
> - 背景轨用半透明白色而非深灰色，与桌面深蓝渐变背景搭配更自然。
> - 填充宽度 = `(已用 / 总量) × 50dp`，实时计算。

#### 行内布局

```
[图标 14dp] [5dp] [文字 11sp 白色] [弹性间距] [进度条 50dp] [3dp] [百分比 9sp]
```

- 整行高度 22~24dp（与现有硬编码行一致），进度条与文字在同一行内
- 进度条垂直居中对齐
- 使用时长行不加进度条，文字后留白

## 七、权限需求

| 类型 | 权限 | 说明 |
|------|------|------|
| 日历 | 无 | 纯本地日期计算 |
| 内存信息 | 无 | `ActivityManager` 公开 API |
| 存储信息 | 无 | `StatFs` 公开 API |
| 使用时长 | `PACKAGE_USAGE_STATS` | 需用户在系统设置中授权「使用情况访问权限」 |

### 使用时长权限处理

- 添加使用时长组件时，不检查权限，直接添加
- 桌面显示时检查权限：
  - 已授权 → 正常显示使用时长
  - 未授权 → 显示 `今日: 需授权`，点击/确认键进入编辑时提示「该组件不可编辑」（统一行为）
- 用户可通过桌面设置的其他入口引导授权（后续实现）

## 八、Android 版本兼容性

项目 `minSdk=14`（Android 4.0），以下组件需注意版本差异。

### 8.1 使用时长组件（TYPE_USAGE）

**`UsageStatsManager` 是 API 21（Android 5.0）引入的 API，Android 4.4 及以下完全不可用。**

#### 判断逻辑

```java
public static boolean isUsageStatsAvailable() {
    return Build.VERSION.SDK_INT >= Build.VERSION_CODES.LOLLIPOP;  // API 21
}
```

#### 各界面行为

| 界面 | API ≥ 21 | API < 21 |
|------|---------|---------|
| S6 类型选择页 | 「使用时长」正常可选 | **「使用时长」灰色不可选**，光标跳过此项 |
| 桌面显示 | 正常显示时长 | 如果已添加（如从高版本迁移数据），显示 `今日: 需 Android 5.0+`，不可选（焦点跳过） |
| S1 设置列表 | 正常显示 | 显示 `使用时长 (不兼容)`，灰色文字，确认键 Toast「此组件需要 Android 5.0 以上」 |
| S3 删除模式 | 正常勾选删除 | 正常勾选删除（允许用户删掉不兼容的组件） |

> 用户可能从高版本备份恢复数据到低版本设备，导致存在不兼容的组件。
> 这种情况下组件可见但不可用，用户可以删除它。

#### S6 类型选择页视觉

```
┌────────────────────────────────┐
│ 选择组件类型                    │
├────────────────────────────────┤
│ [ ] 应用          [ ] 网址      │
│ [ ] 日历          [ ] Activity快捷│
│ [ ] 内存信息      [ ] 存储信息   │
│ [·] 使用时长  (需Android 5.0+)  │  ← 灰色 + 提示文字，不可选
└────────────────────────────────┘
```

### 8.2 存储信息组件（TYPE_STORAGE）

**`StatFs` 在 API 18 起推荐使用 Long 版本方法，旧方法在 API 13 以下返回 int 有溢出风险。**

#### 版本分支

```java
public static long getAvailableBytes(String path) {
    StatFs stat = new StatFs(path);
    if (Build.VERSION.SDK_INT >= 18) {
        // API 18+: 使用 Long 版本（准确）
        return stat.getAvailableBlocksLong() * stat.getBlockSizeLong();
    } else {
        // API < 18: 使用废弃的 int 版本（4.4 走这里）
        return (long) stat.getAvailableBlocks() * stat.getBlockSize();
    }
}

public static long getTotalBytes(String path) {
    StatFs stat = new StatFs(path);
    if (Build.VERSION.SDK_INT >= 18) {
        return stat.getBlockCountLong() * stat.getBlockSizeLong();
    } else {
        return (long) stat.getBlockCount() * stat.getBlockSize();
    }
}
```

> Android 4.4（API 19）≥ 18，实际走 Long 版本分支，**无兼容性问题**。
> 仅 API 14~17 走旧方法，强转 long 避免溢出。

### 8.3 内存信息组件（TYPE_MEMORY）

`ActivityManager.getMemoryInfo()` 自 API 1 起可用，**全版本兼容，无问题**。

### 8.4 日历组件（TYPE_CALENDAR）

纯本地日期计算 + 农历转换，不依赖系统 API，**全版本兼容，无问题**。

### 8.5 矢量图加载兼容性

四种类型的图标均为 vector drawable。Android 4.4（API 19）在布局 XML 中用 `android:src` 引用 `<vector>` 会崩溃。

| 加载场景 | 正确写法 | 错误写法 |
|---------|---------|----------|
| 布局 XML | `app:srcCompat="@drawable/ic_keydroidx_xxx"` | `android:src="@drawable/ic_keydroidx_xxx"` |
| 代码加载 | `ContextCompat.getDrawable()` / `AppCompatResources.getDrawable()` | `getResources().getDrawable()` |
| 颜色切换 | `drawable.setColorFilter()` | `drawable.setTint()` |

> 布局根标签必须声明 `xmlns:app="http://schemas.android.com/apk/res-auto"`。
> 详见 `安卓 4.4（API 19）矢量图崩溃修复计划.md`。

### 8.6 兼容性汇总

| 组件 | 最低 API | 4.4 兼容性 | 处理方式 |
|------|---------|-----------|---------|
| 日历 | 1 | ✅ | 矢量图用 `app:srcCompat` / `ContextCompat.getDrawable()` |
| 内存信息 | 1 | ✅ | 同上 |
| 存储信息 | 1 | ✅ | 同上 + API < 18 用旧 `StatFs` 方法 + long 强转 |
| 使用时长 | **21** | ❌ | S6 灰掉不可选；已添加的显示不兼容提示。矢量图加载同上 |

## 十、完整生命周期

```
添加：S6 选类型 → 直接 addItem → 回 S1
  │
浏览：S1 列表显示实时数据
  │
编辑：S1 确认键 → Toast「该组件不可编辑」→ 任意键消失
  │
排序：S2 → S4/S5 → 正常排序
  │
删除：S2 → S3 → 正常勾选删除
```
