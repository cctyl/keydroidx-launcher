## 一、需求回顾（已确认的决策）

1. **所有界面都有底部菜单栏**：左/右各一个软键（可隐藏，可只有 1 个）、中间显示当前界面名。
2. **顶部标题直接不要了**，界面名只显示在底部菜单栏中间。
3. **桌面时中间不显示界面名**（底部中间留空），顶部也不显示。
4. **左软键 =「选项」的诺基亚风格弹窗**（UI + 按键分发）做成全项目通用组件。
5. **弹窗做完整版**：支持「点击后不关闭 + 动态刷新文案」（全选/取消全选场景），连 `NokiaWidgetDeleteDialog` 一起收敛。
6. **每页按钮文字、功能、界面名可自定义**。
7. **过渡策略：一步到位**——新建组件后直接替换所有现有界面并清理旧类。

## 四、核心设计

### 4.1 `NokiaPage` 接口 —— 页面声明菜单栏差异

新增接口，页面 Fragment 实现它，用 **getter 声明"当前状态下"的菜单栏**（getter 可动态取值，状态变化后主动刷新）：

```java
package ru.playsoftware.j2meloader.nokia;

/**
 * 诺基亚页面契约：声明底部菜单栏差异。
 * <p>
 * 页面实现该接口后，由 {@link NokiaDesktopActivity} 在页面切到前台 / 页面主动请求时
 * 自动装配底部菜单栏（setBottomBar），页面自身不再直接操作 bottomLeft/bottomCenter/bottomRight。
 * <p>
 * 三个 getter 允许<b>动态取值</b>：页面内部状态（焦点、mode）变化后，
 * 调用 {@code host.refreshPageBar()} 即可重新装配。
 */
public interface NokiaPage extends NokiaFocusHost {

    /** 底部菜单栏中间显示的界面名；返回 null 则隐藏（如桌面）。 */
    String getPageTitle();

    /** 左软键文字；返回 null 则隐藏。 */
    String getSoftLeftText();

    /** 右软键文字；返回 null 则隐藏。 */
    String getSoftRightText();
}
```

> 说明：`NokiaFocusHost` 里已有的 `onDirection/onSelect/onSoftLeft/onSoftRight/onBack` 仍是按键语义的入口，`NokiaPage` 只新增"菜单栏声明"三个 getter，不冲突。

### 4.2 `NokiaDesktopActivity.refreshPageBar()` —— 自动装配

在 `NokiaDesktopActivity` 新增公共方法，检测当前顶层 Fragment 是否实现 `NokiaPage`，是则自动装配：

```java
/** 重新读取当前页面的 NokiaPage 声明并装配底部菜单栏。 */
public void refreshPageBar() {
    Fragment f = getSupportFragmentManager().findFragmentById(R.id.midPanel);
    if (f instanceof NokiaPage) {
        NokiaPage page = (NokiaPage) f;
        setBottomBar(page.getSoftLeftText(), page.getPageTitle(), page.getSoftRightText());
    }
}
```

调用时机：
- Fragment 的 `onViewCreated` / `onResume` 里调用 `host.refreshPageBar()`（替代原来写死的 `setBottomBar(...)` 与 `topTitle` 设置）；
- 页面内部状态变化（Box 焦点切换、WidgetSettings mode 切换、KeyBind 覆盖模式、向导三态）时调用 `host.refreshPageBar()`。

> `findFragmentById(R.id.midPanel)` 与实际布局 id 对齐；若 Activity 用 `replace` 切换，顶部 fragment 就是当前页，逻辑成立。

### 4.3 `NokiaOptionsDialog` 通用选项弹窗（完整版）

数据模型 + 完整能力，一个类收敛三个旧弹窗：

```java
package ru.playsoftware.j2meloader.nokia;

/**
 * 通用诺基亚风格选项弹窗。
 * <p>
 * 底部锚定、标题栏 + 选项列表 + 自带底部软键栏（软键只显示文字，无高亮）。
 * 支持：任意数量选项、禁用项跳过、点击后不关闭（keepOpen）、动态刷新文案（setItems）。
 * 按键经 {@link NokiaKeyBinding} 解析：上/下移动、确认键/左软键执行、右软键/返回关闭。
 */
public class NokiaOptionsDialog extends DialogFragment {

    /** 单个选项的数据模型。 */
    public static class OptionItem {
        public final int icon;        // 图标资源，0=无图标
        public final String label;    // 文案（setItems 后可更新）
        public final boolean enabled; // false=灰色不可选，方向键跳过
        public final boolean keepOpen;// true=点击后不关闭（用于全选/取消全选后刷新）
        public final Runnable action; // 点击动作

        public OptionItem(int icon, String label, boolean enabled,
                          boolean keepOpen, Runnable action) { ... }
    }

    /** 打开弹窗。 */
    public static NokiaOptionsDialog show(FragmentManager fm,
                                          String title,
                                          List<OptionItem> items) { ... }

    /** 动态刷新全部选项（重建列表 + 保留/修正焦点），用于 keepOpen 场景。 */
    public void setItems(List<OptionItem> items) { ... }

    /** 关闭弹窗（供 action 内主动调用，例如 keepOpen=false 时也要可主动关）。 */
    @Override public void dismiss() { ... }
}
```

能力对照旧弹窗：

| 旧能力 | 新实现 |
|---|---|
| 写死 3 行 / 参数化数组 | `List<OptionItem>` 任意数量 |
| 禁用项灰色 + 跳过 | `enabled=false`，`moveFocus` 跳过 |
| 点击行触发 | `row.setOnClickListener → trigger(index)` |
| 全选/取消全选（点击不关闭+刷新文案） | `keepOpen=true`，action 里更新宿主状态后 `setItems(...)` 重建 |
| 删除已选（文案带数量、禁用态） | `enabled = count>0`，label 动态拼 |
| 按键分发 | 统一 `setOnKeyListener` + `NokiaKeyBinding.resolveAction` |
| 窗口配置/高亮/forceNonTouchMode | 类内统一实现一次 |

布局复用 `dialog_nokia_widget_options.xml`（标题栏 `widgetOptionsTitle` + 列表容器 `widgetOptionsList` + 软键栏），**不改 id、不新建布局**。

### 4.4 软键栏规范遵守（重申）

- 弹窗底部软键栏只有「选择 / 返回」两个文字标签，**无焦点、无高亮**（现有布局已符合，不动）。
- 弹窗选项行用 `bg_nokia_selected_dark` 高亮（方向键导航选中项），合理。
- 确认键/左软键触发选中行；右软键/返回关闭；左右方向键忽略。

## 六、风险与注意

1. **覆盖模式中间改文字**是唯一交互行为变化，需拍板（见 5.4 的 ⚠ 项）。
2. **`NokiaKeyBindWizardFragment` 录制态**要隐藏底部栏：`getSoftLeftText()/getSoftRightText()` 返回 `null` 即可，`refreshPageBar()` 会 GONE 掉。
3. `NokiaMenuFragment` 原有 `br.setOnClickListener(v -> host.exitCurrent())` 的直接绑定（第 151 行）应移除，触摸已由 Activity 的 `bindBottomBarTouch()` 统一处理。
4. 弹窗 `setItems()` 重建列表后，若焦点项被禁用，需自动修正焦点到最近可用项（复用现有 `moveFocus` 逻辑）。
5. 日志：新类关键路径（打开/刷新/关闭/按键动作）都打 `NokiaLog.i/d`。
6. 兼容 240×320：弹窗行高 40dp、软键栏 28dp、标题 28dp 与现有完全一致，无新增尺寸风险。

## 七、待审核确认项

1. **按键绑定覆盖模式中间文字「选择」→ 改为固定界面名「按键绑定」**：
   `NokiaKeyBindFragment` 的覆盖确认模式原本把**中间位置**当按钮显示 `"选择"`（`bc.setText("选择")` + `setBottomBar("取消","选择","覆盖")`）。按新规范中间是界面名，建议改成：覆盖确认动作由左软键（`"取消"`）或右软键（`"覆盖"`）触发，中间始终显示 `"按键绑定"`。**该交互变更是否可接受？**
2. **`NokiaPage` 命名与签名**：`getPageTitle()` / `getSoftLeftText()` / `getSoftRightText()` 三个 getter 是否满足需求？是否改名为更通用的 `getCenterText()`？
