# 图标包与图标替换设计

> 目标：桌面引入「图标包」机制（外观设置全局切换 + 功能表单应用替换），并让内置 S60 图标
> 以**标准 ADW 映射表**驱动，取代原先的 Java 通配匹配。

## 1. 功能与入口

| 入口 | 位置 | 说明 |
| :--- | :--- | :--- |
| 全局图标包 | 桌面设置 → 外观与显示 → 「图标包：xxx」 | 可选：内置 S60 图标包 / 设备已装 ADW 图标包 / 不使用图标包（使用原图标） |
| 单应用替换 | 功能表 → 左软键「选项」→ 更换图标 | 先选图标包（列表含内置 S60 与各已装包）→ 分页图标网格挑选 → 保存为该应用的覆盖 |
| 恢复默认 | 功能表 → 选项 → 恢复默认图标 | 仅在该应用存在覆盖时出现；清除覆盖，回到按全局图标包解析 |

解析优先级（`KeydroidxIconResolver`）：**单应用覆盖 → 全局图标包命中 → 应用自身原图标**。
图标包未收录的应用一律回退应用原图标（冻结/停用应用走 `loadIconWithFallback` 降级，仍能出图）。

## 2. 代码结构

```
nokia/
├── iconpack/
│   ├── KeydroidxIconPack          图标包抽象（映射→图标名、图标名→Drawable）
│   ├── KeydroidxAdwIconParser     ADW XML 解析（appfilter.xml + drawable.xml）
│   ├── KeydroidxAdwIconPack       统一实现：内置包读 assets，外部包读 res/xml|res/raw|assets
│   ├── KeydroidxS60Icons          内置 49 个 s60_* 的显式资源表 + 中文标签（禁用 getIdentifier）
│   ├── KeydroidxIconPackManager   图标包清单/枚举/按 ID 取包（后台单飞）
│   └── KeydroidxIconResolver      统一解析入口 + 缓存键 + 失效 + 预热
├── KeydroidxIconPackSettingsFragment  图标包选择页（全局模式 / 单应用模式）
├── KeydroidxIconPickerFragment        图标挑选页（分页网格，4 列）
└── KeydroidxSettingsStorage           新增 icon_pack_id / icon_overrides 读写
assets/s60/appfilter.xml               内置映射表（纯包名写法，当前 120 条）
assets/s60/drawable.xml                内置可挑选图标清单（45 项）
```

## 3. ADW 支持范围

**支持**：`appfilter.xml` 的静态 `<item component drawable>`；`drawable.xml`（图标挑选清单）。
`component` 同时支持标准 `ComponentInfo{pkg/cls}` 与**本项目扩展写法「纯包名」**
（内置 S60 用纯包名表达「整包映射」，与原精确包名表一一对应）。

**不支持（明确忽略，未命中即回退原图标）**：`<calendar>` 动态日历、`<dynamic-clock>`、
`<iconback>/<iconmask>/<iconupon>/<scale>` 自动生成回退图标、伪 component（`:BROWSER` 等）。
解析时逐条 `d` 日志，不报错、不影响其它条目。

**查找规则**：组件级表优先级高于包级表；组件级条目在包级表空缺时会补一条包名兜底
（同一应用的其它启动入口也能命中）。`ResourceName` 取图用
`PackageManager.getResourcesForApplication(pkg)` + `Resources.getIdentifier(name,"drawable",pkg)`
（API 19+ 可用，不使用反射构造 `Resources`）。

## 4. 内置 S60 包：纯映射化（本次改造的核心）

- 原 `KeydroidxS60IconMap` 的**精确包名表**（108 条）转换为 `assets/s60/appfilter.xml`，
  并补齐功能表「固定槽位」的候选包名，共 **120 条**；
- 原**名称关键词层**（`LABEL_FALLBACK`）与**意图探测层**（`PROBES`/`initAsync`/持久化缓存）
  **整体下线**，`KeydroidxS60IconMap` 已删除；
- 内置图标名 → 资源 id 走 `KeydroidxS60Icons` 的显式 `int[]` + 名称表（49 项），
  避免 release 资源收缩把只被字符串引用的 `s60_*` 裁掉。

### 由此产生的行为变更（有意，需知悉）

1. 原先靠「名称关键词 / 意图探测」命中 S60 图标、但不在映射表内的应用，现在**回退应用原图标**；
   可在功能表用「更换图标」手动补齐（这也是下线这两层的主要理由：手动替换比猜测更准）。
2. 功能表分组排序语义由 `s60IconResId != 0` 改为「是否被当前图标包命中」（`iconPackName != null`），
   排序结果随当前图标包变化。
3. `PINNED_SLOTS` 固定槽位图标（日历/联系人/电话/浏览器/信息/多媒体/文件/商店/相机/设置）
   **仅在当前图标包为内置 S60 时生效**；切到外部包或「不使用图标包」时保留图标包解析结果或原图标。
4. 外部图标包（如 2017 年的 `S60Icons`）覆盖率通常很低——实测该包只命中设备上 27 个应用中的 1 个，
   其余回退原图标，属预期。

## 5. 缓存与一致性

- 缓存键：`包名` 或 `包名|图标包ID|图标名`（`KeydroidxIconResolver.buildCacheKey`）。
  **键在后台线程重算**（`KeydroidxAppIconCache.loadInternal`），保证「落盘的键」与
  「实际加载到的图标」严格一致；主线程只用它做内存快路径。
- 磁盘目录升级为 `cache/app_icons_v5/`，文件名 `包名.png` 或 `包名__hash.png`，
  另存「文件名 → 完整键」副表做精确校验（避免 hash 冲突串图）。
- 失效：切换图标包 → `invalidateAll()`（内存 + 磁盘 + 副表全清，并释放外部包 Resources）；
  写/清单应用覆盖 → `invalidate()`（只清该应用）。
- 功能表进程内列表缓存带「图标外观指纹」（`getIconStateFingerprint` = 图标包 ID + 覆盖摘要）；
  指纹变化即视为无缓存并清空旧 `items`，避免返回功能表仍显示旧图标（含后台校准误判「列表无变化」）。

## 6. 线程与性能

- 映射表解析、图标包枚举、跨包位图加载全部在后台线程；沿用「单飞标记 + 主线程回调」模式。
- 主线程不做 IO：映射表未就绪时主线程解析直接返回「未命中」并触发预热，预热完成后回调刷新
  （桌面首屏、功能表首帧因此不会卡在文件 IO 上）。
- 实测：内置包（120 条）解析 **8~16ms**，可挑选 44 项；外部 `S60Icons` 包（159 条映射 / 42 图标，
  忽略 12 条伪 component）解析 **13ms**；图标包枚举 **4~5ms**。

## 7. 包可见性（必须）

`AndroidManifest.xml` 的 `<queries>` 必须声明两个主题 intent，否则 Android 11+ 查不到图标包、
也读不到其资源：

```xml
<intent><action android:name="org.adw.ActivityStarter.THEMES" /></intent>
<intent><action android:name="com.novalauncher.THEME" /></intent>
```

## 8. 扩展指引

- **新增内置 S60 图标**：① 放 `res/drawable-nodpi/s60_xxx.png`；② 在 `KeydroidxS60Icons`
  的 `IDS/NAMES/LABELS` 三处同步（顺序必须一致）；③ 如允许手动挑选，加入 `assets/s60/drawable.xml`。
- **新增图标包来源**（如自家云端包）：实现 `KeydroidxIconPack` 子类并在
  `KeydroidxIconPackManager.getPacks()/findPack()` 中登记即可，解析链路与 UI 无需改动。
- **图标覆盖格式**：`nokia_desktop_settings` 的 `icon_overrides`
  = `{"包名":{"pack":"s60_builtin|adw:<pkg>","icon":"图标名"}}`；未知/已卸载的图标包会回退内置 S60。
- **生态对齐**：`KeyProvider` 的 `/settings` 游标已新增 `icon_pack_id` 行。

## 10. 已修复的坑（实现时踩过，改动别踩回去）

1. **切换图标包后，列表里其它包的预览图退化成默认图标**（看起来像「都变成 S60 图标」）：
   `KeydroidxIconResolver.invalidateAll()` → `KeydroidxIconPackManager.invalidate()` 会释放**所有**
   已装包已解析的映射表（`loaded=false`），而设置页的行仍持有这些实例 → `listIconNames()` 变空 →
   预览回落到 `R.mipmap.ic_launcher`（其图标恰与 S60「应用」图标观感相近，易误判）。
   两处修复：① `scanInstalled()` **复用已有实例**（按 `lastUpdateTime` 判断包被升级才 `release()`，
   卸载的清掉），不再每次枚举都换新实例；② 切换/重置后 `warmUpPreviewIconsAsync()` 重新解析，
   完成后重建列表。
2. **切换时预览闪一下（先占位图再变回来）**：切换并不改变图标包清单，没必要丢弃映射表。
   已把 `KeydroidxIconResolver.invalidateAll()` 里的「释放所有包映射」去掉 —— 它现在只清
   「应用 → 图标」缓存（内存 + 磁盘）与通知缓存，再预热新图标包；
   映射表的失效只由 `scanInstalled()` 按 `lastUpdateTime`/卸载精确触发。
3. **固定槽位图标会盖掉用户手动指定的图标**：`PINNED_SLOT_ICONS` 原先无条件覆盖，
   现改为「该包存在单应用覆盖时不覆盖」，保证用户选择优先。
4. **图标包页的预览需要解析才能出图**：进入页面/切换后都走 `warmUpPreviewIconsAsync()`，
   就绪后回调 `rebuildList()`；不要在解析未完成时把结果当成「该包没有图标」。

## 11. 已知取舍

- `drawable.xml` 缺失的外部包：挑选清单退化为 `appfilter.xml` 中出现过的图标名（可能较大）。
- 外部包首次进入挑选页需解析（约十几 ms），期间显示「正在读取图标包…」。
- 未实现 ADW 的 `calendar`/`dynamic-clock`/`iconback` 等扩展（优先级低，未命中即回退，不影响主流程）。
- 组件级映射不支持通配（如 `pkg/*`），仅精确类名或纯包名。
