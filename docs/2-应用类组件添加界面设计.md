# 2-应用类组件添加/编辑界面设计

> 本文档定义应用选择界面（`KeydroidxWidgetAppPickerFragment`）的完整交互。
> 同一界面通过 Bundle 参数区分**添加模式**与**编辑模式**：
> 添加模式从 S6 类型选择进入，编辑模式从 S1 确认键进入。
> 参考 `KeydroidxMenuFragment` 的宫格布局与分页导航模式，列数按屏幕宽度自适应，增加搜索框与已添加标记。

---

## 一、界面层级关系

```
S6 选择组件类型 → 选「应用」
  └─ 应用选择界面 (KeydroidxWidgetAppPickerFragment, mode=ADD)  ← 添加模式
       └─ 确认键选一个应用 → addItem() → 回到 S1

S1 桌面组件设置 → 确认键（光标在应用类组件上）
  └─ 应用选择界面 (KeydroidxWidgetAppPickerFragment, mode=EDIT)  ← 编辑模式（同一界面）
       └─ 确认键选一个新应用 → updateItem() → 回到 S1
```

### 添加 vs 编辑 — 同一界面，两种模式

应用类组件的编辑行为是"换绑"：把当前绑定的应用换成另一个。
不需要单独的编辑表单（应用组件没有额外的可编辑属性），
直接复用应用选择界面，通过 `Bundle` 参数区分模式：

| 维度 | 添加模式 | 编辑模式 |
|------|---------|---------|
| 入口 | S6 → 选「应用」 | S1 → 确认键（光标在应用类组件上） |
| Bundle | `mode=ADD` | `mode=EDIT, editIndex=N` |
| 标题 | 「选择应用」 | 「更换应用」 |
| 当前已添加的灰色标记 | 所有已添加应用灰色 | **当前编辑的这个应用例外**：它不标记为灰色，正常可选（允许"换为自己"=不变） |
| 确认键 | `storage.addItem(item)` → S1 | `storage.updateItem(editIndex, item)` → S1 |
| 右软键 | 回到 S6 | 回到 S1 |

## 三、宫格规格

参考 `KeydroidxMenuFragment` 的布局思路，列数和行数均按屏幕分辨率自适应：

### 列数计算

- 每个格子最小宽度 72dp（图标 36dp + 两侧间距）
- 列数 = `clamp(3, floor(可用宽度dp / 72), 5)`
- 即最小 3 列、最大 5 列

### 行数计算

- 复用 `KeydroidxMenuFragment.computeRowsPerPage()` 逻辑：**基于实测 panelH 反推**，禁止估算公式
- 通过 `((KeydroidxDesktopActivity) requireActivity()).getMidPanelHeight()` 取 midPanel 真实像素高度
- `availDesign = panelH(px) / density / scale`，再 `rows = clamp(3, floor((availDesign - TITLE_H_DP) / ROW_H_DP), 8)`
- ROW_H_DP ≈ 64dp 仅作为 fallback 值；行高均分拉伸 = `(availDesign - TITLE_H_DP) / rows`
- `computeRowsPerPage()` 须 `view.post(() -> { ... })` 延迟到 midPanel 布局完成后执行
- 禁止自行计算 scale，统一走 `((KeydroidxDesktopActivity) requireActivity()).getScale()`

### 其他参数

- **每页数量**：`columns × rowsPerPage`
- **格子背景**：未选中透明，选中蓝色高亮（`bg_nokia_selected_dark`）
- **图标大小**：36×36dp
- **文字大小**：9sp，白色，单行省略
- **列间距均匀分布**：每列等宽，`layout_weight=1`

## 五、已添加应用的标记

已在组件列表中的应用，其宫格需要**灰色标记**，不可选中：

### 视觉样式

| 状态 | 图标 | 文字 | 背景 |
|------|------|------|------|
| **正常** | 正常彩色 | 白色 `#FFFFFF` | 透明 |
| **已添加** | 半透明（alpha ~30%） | 灰色 `#666666` | 浅灰底 |
| **当前编辑项**（仅编辑模式） | 正常彩色 | 白色 | 浅蓝底 + 右上角 `📌` 角标 |

> 参考诺基亚 S60：已使用的项变灰不可选，类似"已安装"的禁用态。

### 交互行为

**添加模式**：
- 光标可以移动到已添加的格子上（允许路过）
- 但按**确认键时不响应**（无任何动作）
- 灰色格子被高亮选中时，依然显示蓝色选中框，但确认键无效

**编辑模式**：
- 进入时，当前绑定的应用格子标记为「当前编辑项」（浅蓝底 + 📌角标），光标优先定位到此格
- **当前编辑项确认键也不响应**（换为自己无意义）
- 编辑项不被标记为灰色——它是正常可选的视觉样式，只是确认键无效
- 除当前编辑项之外的其他已添加应用，依然灰色、确认键无效
- 用户只能选择**未添加**的应用 → `updateItem(editIndex, newItem)` → 回到 S1
- 如果所有未添加的应用都已选完 → 全灰，只能右软键返回

> ⚠️ **按键配对规范（DOWN/UP 成对消费）**：本编辑页由 S1 确认键（编辑模式）或 S6 确认键（添加模式）进入；确认键选中应用回到 S1 时，若确认键 DOWN 已在 `KeydroidxDesktopActivity.dispatchKeyEvent` 本层被消费，须同步消费对应的 UP（含 REPEAT），禁止只消费 DOWN 就放手。否则 DOWN 被本层吞掉、UP 穿透到新页面的可点击 View 时，系统会在 UP 合成 `performClick()` 触发第二次动作（典型：进入后又自动选中第一项）。实现用 `lastHandledDownKeyCode` 记录被本层消费的 keyCode，非 DOWN 分支对相同 keyCode `return true` 吞掉，未消费键 DOWN 路径复位为 `KEYCODE_UNKNOWN`。搜索框 EditText 编辑态按键不受此约束（走系统软键盘）。

## 六、搜索功能

### 搜索框本质

搜索框像宫格里的一个格子一样被方向键选中，确认键激活编辑态。

Android 上没有诺基亚 T9 物理键盘，方向键和字母输入是分离的，
因此采用两步激活：光标选中搜索框 → 确认键 → 软键盘弹出 → 打字过滤。

### 搜索框的外观

### 焦点进入搜索框

| 触发方式 | 说明 |
|---------|------|
| 宫格第一行按**上键** | 焦点从宫格移到搜索框，搜索框蓝色高亮 |

> 不响应物理键盘字母键自动跳转。Android 设备的方向键和字母键是分开的，
> 直接在宫格按字母没有确定的焦点目标。

### 搜索框聚焦时的按键处理

搜索框处于焦点态（蓝色高亮但未激活 EditText）：

| 按键 | 行为 |
|------|------|
| 上 | 焦点回到宫格第一行 |
| 下 | 焦点回到宫格第一行 |
| 确认键 | **激活 EditText** → 弹出系统软键盘 → 进入编辑态 |
| 左/右 | 无效果 |
| 左软键 | 无效果 |
| 右软键 | 回到 S6 |

### 编辑态（EditText 激活后）

软键盘弹出后，搜索框是标准 Android EditText，用户通过软键盘打字：

- 输入任意字符 → 实时过滤宫格（通过 `TextWatcher`）
- 软键盘上的回车/完成键 → 关闭软键盘，焦点回到宫格第一行
- 按物理返回键 → 关闭软键盘，焦点留在搜索框（回退到焦点态）
- 右软键 → 关闭软键盘 + 回到 S6
- 退格删空搜索文字 → 恢复完整应用列表

> 编辑态期间宫格方向键仍可正常导航（用户可以在过滤后的宫格中移动光标选应用），
> 因为焦点切换到宫格后 EditText 自动失焦、软键盘收起。

### 实时过滤

- 每次搜索文本变化时，立即过滤宫格内容（`TextWatcher.onTextChanged`）
- 对应用名称做**包含匹配**（不区分大小写）
- 匹配的应用显示在宫格中，不匹配的隐藏
- 搜索框有文字时显示「匹配 X 个应用」计数
- 如匹配结果 ≤ perPage，不显示分页（单页显示全部）
- 如匹配结果 > perPage，显示分页页码并重置焦点到第一格
- 清空搜索文本（退格删完）→ 恢复完整应用列表，恢复分页

### 焦点视觉效果

| 状态 | 搜索框外观 | 宫格 |
|------|-----------|------|
| 焦点在宫格 | 正常底色，无高亮 | 光标所在格蓝色高亮 |
| 焦点在搜索框 | 蓝色高亮（复用 `bg_nokia_selected_dark`） | 无光标 |
| 编辑态 | 蓝色高亮 + 系统光标闪烁 + 软键盘弹出 | 无光标 |

## 七、完整按键行为

### 宫格导航（列数自适应 3~5 列）

| 按键 | 行为 |
|------|------|
| 上 | 同列上移一行；到第一行后再按上 → 焦点移到搜索框 |
| 下 | 同列下移一行；到最后一行后再按下 → 翻下一页（如有） |
| 左 | 同行左移一格；到最左再按左 → 不动（不回绕） |
| 右 | 同行右移一格；到最右再按右 → 不动（不回绕） |
| 确认键 | 选中当前应用，添加为组件 → 回到 S1（已添加的灰色格子不响应） |
| 左软键 | 无效果 |
| 右软键 | 回到 S6 |

### 翻页

| 翻页方式 | 行为 |
|---------|------|
| 宫格最后一行按「下」 | 翻到下一页，焦点保持同列 |
| 宫格第一行按「上」（不在搜索框时） | 焦点移到搜索框（不翻页） |
| 触摸滑动 | 上滑/左滑 → 下一页；下滑/右滑 → 上一页 |

> 代码层面注意：`KeydroidxMenuFragment` 的 `onDirection` 中 `ACTION_UP` 在第一行时会 `pagePrev()` 翻上一页，而本页面第一行按上应该是跳搜索框。需要 override 这个行为。

### 搜索态按键

> 详见第六章。搜索框有三种状态：①焦点态（上/下退出，确认键激活），②编辑态（软键盘输入，宫格方向键仍可导航），③无焦点（光标在宫格时）。

## 八、数据流

```
进入页面（添加模式）
  │
  ├─ 加载安卓应用列表（PackageManager）
  ├─ 加载 J2ME 应用列表（异步，读取 DB）
  ├─ 读取已添加组件列表（KeydroidxWidgetStorage.getItems()）
  ├─ 标记已添加应用 → 灰色 + 不可选
  ├─ 按名称排序
  └─ 构建宫格

进入页面（编辑模式）
  │
  ├─ 同上加载应用列表 + 已添加组件列表
  ├─ 从 arguments 取 editIndex，找到当前绑定应用
  ├─ 该应用特殊标记「当前编辑项」（浅蓝底 + 📌），不放回灰色
  ├─ 其余已添加应用 → 灰色 + 不可选
  ├─ 光标优先定位到当前编辑项所在格
  └─ 构建宫格

用户选中某应用（确认键）
  │
  ├─ 添加模式 → KeydroidxWidgetStorage.addItem(item) → exitCurrent → 回到 S1
  └─ 编辑模式 → KeydroidxWidgetStorage.updateItem(editIndex, item) → exitCurrent → 回到 S1
```

## 九、边界情况

| 场景 | 处理 |
|------|------|
| **添加模式：所有应用都已添加** | 列表全部灰色，用户无法选中任何应用，只能右软键返回 |
| **编辑模式：只剩当前这个应用未重复** | 全灰（当前编辑项确认键也无效），用户只能右软键返回 |
| **搜索无结果** | 宫格区域显示「未找到匹配应用」 |
| **正在加载 J2ME 应用** | 先显示安卓应用，J2ME 加载完后自动补入列表并刷新宫格 |
| **J2ME DB 不存在** | 静默跳过，只显示安卓应用 |
| **用户反复进入/退出本页** | 每次进入都重新加载应用列表（保证最新状态） |
| **editIndex 越界** | 降级为添加模式 |
