# 桌面权限管理规范与解冻权限失效自愈设计方案

## 1. 背景与问题定位

### 1.1 现状与痛点
1. **解冻应用偶发性失败**：
   - 用户在桌面上解冻应用时，`pm enable <pkg>` 通过 Shizuku/Root 执行成功，但在执行 `pm.getLaunchIntentForPackage(pkg)` 拉起应用时失败。
   - 现象表现为：解冻失败，不知原因；用户不知在何处操作之后，系统才突然弹出“读取应用列表权限”的授权窗口，授权后功能才恢复正常。
2. **权限缺少主动批量授权时机**：
   - 首次启动或重新配置向导结束后，没有统一向用户集中申请桌面运行所必需的权限（应用列表、电话状态/双卡信号、通知等），导致各功能在后续运行中被动碎片化弹窗，严重破坏全键盘诺基亚交互的沉浸感。
3. **权限静默丢失缺乏自愈能力**：
   - Android 13+ 具备权限自动重置（auto-reset）机制，且国内厂商定制 ROM（如展锐平台、MIUI/HyperOS 等）会在系统安全清理、省电优化或策略变更时撤销敏感权限。
   - 权限一旦丢失，业务层直接受阻崩溃或静默失败，缺乏“执行前预检”、“执行失败后智能诊断”、“自动唤起授权”以及“授权完成后无缝断点续传（重试）”的自愈链条。

### 1.2 设备与系统底层深度排查（展锐 ums9620 / Android 13 真机）
经对已连接的真机设备（FIH Q968，Android 13，展锐 ums9620 芯片）深度排查确认：
1. **清单文件缺失官方规范声明**：
   - `AndroidManifest.xml` 中未声明 Android 11+ 原生 Launcher 官方规范的 `<uses-permission android:name="android.permission.QUERY_ALL_PACKAGES" />`。
   - `AndroidManifest.xml` 中未声明国内工信部 CTA 规范在展锐芯片平台特有的运行时危险权限：
     `com.unisoc.permission.CTA_QUERY_ALL_PACKAGES`（prot=dangerous，归属于应用列表安全管控）。
   - 未声明小米 HyperOS/MIUI 等 ROM 使用的 `android.permission.GET_INSTALLED_APPS`。
2. **系统底层拦截行为**：
   - 展锐 ROM 的 `unisoc-res.apk` 中将 `com.unisoc.permission.CTA_QUERY_ALL_PACKAGES` 设定为危险权限。当应用未获此权限时，PackageManager 对查询、获取 Intent 的调用会被 CtaSecurity 拦截，导致 `getLaunchIntentForPackage()` 返回 null 或抛出异常。
   - 之前项目未主动申请该权限，仅当系统层在特定前台时序下偶然触发 CTA 弹窗时用户才能授权，因此呈现出“不知怎么操作才弹窗”的玄学问题。

## 2. 现有权限申请现状调研

### 2.1 当前项目权限申请方式
经全工程源码检索（`grep -rn "requestPermissions"`）：
- **完全使用原生分散调用**：
  - `NokiaDesktopActivity.java` 内部单独对 `POST_NOTIFICATIONS` 执行原生 `requestPermissions()`。
  - `StatusBarController.java` 内部单独对 `READ_PHONE_STATE` 执行原生 `requestPermissions()`。
  - `ContextHolder.java`（J2ME 运行时）内部封装原生 `ActivityCompat.requestPermissions()`。
- **现存缺陷**：
  1. **无生命周期与结果统一回调体系**：原生调用依赖宿主 Activity 的 `onRequestPermissionsResult` 分发，各模块自成一套，逻辑割裂，难以做链式调用。
  2. **缺少特殊权限与国内厂商定制权限适配**：原生 `requestPermissions()` 无法直接处理展锐 CTA 权限未声明时的静默失败，也无法直接处理通知监听服务（NotificationListener）、无障碍、安装未知应用等特殊权限。
  3. **无“永久拒绝”引导机制**：原生 API 无法优雅地区分“用户首次拒绝”与“用户勾选不再询问”，更无法直接拉起应用专属详情页进行引导。

## 3. 三方库 `com.github.getActivity:XXPermissions` 调研评估

针对是否接入业内主流的 `XXPermissions`，调研结论如下：

### 3.1 核心优势分析
1. **对国内定制 ROM（展锐、MIUI、EMUI、ColorOS、OriginOS 等）支持极佳**：
   - 内置识别各家定制权限（包括针对读取应用列表权限的特殊适配：小米的 `GET_INSTALLED_APPS`、特殊厂商权限映射等）。
2. **极简链式调用与回调**：
   - 基于不可见 Fragment / Activity 实现，无需在宿主 Activity 中重写 `onRequestPermissionsResult`。
   - 支持批量权限合并申请，统一触发 `onGranted(List<String> permissions, boolean allGranted)` 与 `onDenied(List<String> permissions, boolean doNotAskAgain)`。
3. **“永久拒绝”自愈引导完备**：
   - 提供 `XXPermissions.startPermissionActivity()`，能精准适配各 ROM 差异，直接直达应用权限设置页。
4. **轻量与高稳定性**：
   - 纯 Java/Kotlin 实现，无臃肿依赖，在 Android 开源界长期维护（Star 14k+）。

### 3.2 本项目接入可行性与关键考量（必须注意的硬性约束）
1. **MinSdk 兼容性（硬性规则）**：
   - 本项目根据《NOKIA_DEVELOPMENT_RULES.md》要求保持向下兼容（MinSdk 14 / Android 4.4 兼容）。
   - `XXPermissions` 较新版本（v18+ / v20+）的 `minSdkVersion` 通常为 14 或 21。若引入高版本，需在 `AndroidManifest.xml` 中添加 `<uses-sdk tools:overrideLibrary="com.hjq.permissions" />`，且在运行时使用 `Build.VERSION.SDK_INT` 守卫，避免在低版本 Android 上发生类加载异常。
2. **诺基亚风格按键交互约束**：
   - `XXPermissions` 自带的 Dialog（如果使用其自带提示框）是现代 Material/触屏弹窗，**禁止直接使用其自带的 Dialog UI**。
   - **正确用法**：仅使用 `XXPermissions` 的**核心权限调度引擎与权限状态判断能力**；所有展示给用户的“权限解释说明框”与“引导去设置弹窗”，必须使用本项目规范的 `NokiaOptionsDialog` 或基于 240dp 基准的诺基亚黑白/复古像素弹窗，保持左右软键交互统一。

### 3.3 调研结论
**强烈推荐接入 `XXPermissions`（或基于其核心思想封装）**：
- 能彻底解决 Android 6.0 ~ Android 14+ 以及展锐/小米等定制 ROM 下复杂的权限申请、永久拒绝识别和跳转权限页的问题；
- 结合本项目的 `NokiaOptionsDialog` 进行 UI 呈现，既能利用成熟稳定的底层权限兼容引擎，又能严格遵守诺基亚物理按键交互规范。

## 4. 架构设计与实施方案

### 4.1 清单文件（Manifest）层：补齐底层凭证
在 `app/src/main/AndroidManifest.xml` 中增加以下权限声明：
```xml
<!-- Android 11+ (API 30+) 软件包可见性官方权限（桌面 Launcher 必需） -->
<uses-permission android:name="android.permission.QUERY_ALL_PACKAGES"
    tools:ignore="QueryAllPackagesPermission" />

<!-- 展锐（Unisoc）平台 CTA 读取应用列表危险权限（展锐设备解冻与桌面枚举核心） -->
<uses-permission android:name="com.unisoc.permission.CTA_QUERY_ALL_PACKAGES"
    tools:ignore="ProtectedPermissions" />

<!-- 小米等国内 ROM 应用列表读取权限 -->
<uses-permission android:name="android.permission.GET_INSTALLED_APPS"
    tools:ignore="ProtectedPermissions" />
```

---

### 4.2 核心枢纽层：封装 `NokiaPermissionManager`
统一封装权限判断与交互调度：

1. **核心权限定义（Core Permissions）**：
   - **应用列表权限**：`QUERY_ALL_PACKAGES`、`CTA_QUERY_ALL_PACKAGES`、`GET_INSTALLED_APPS`。
   - **顶栏系统信息权限**：`READ_PHONE_STATE`（用于双卡信号、运营商识别）。
   - **桌面通知展示权限**：`POST_NOTIFICATIONS`（Android 13+ 通知栏展示）以及系统通知监听。
   - **必要存储权限**：`READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE`（J2ME 游戏与壁纸导入）。

2. **核心方法设计**：
   - `boolean hasAppListPermission(Context context)`：
     - 检查 API 级别；
     - 检查 `com.unisoc.permission.CTA_QUERY_ALL_PACKAGES`（若是展锐平台）；
     - 实际执行轻量探测（例如尝试 query 某个已知系统包），确保具备真实可见性。
   - `List<String> getMissingCorePermissions(Context context)`：
     - 返回当前缺少的必要核心权限列表。
   - `void requestCorePermissions(Activity activity, Runnable onComplete)`：
     - 批量申请缺失的核心权限。
   - `void requestAppListPermission(Activity activity, PermissionCallback callback)`：
     - 专项申请应用列表权限（支持永久拒绝时弹诺基亚风格引导去设置）。

---

### 4.3 交互层：向导结束批量申请（诉求一）

1. **时机点**：
   - 在物理按键向导 `NokiaKeyBindWizardFragment` 的最后一页（`STATE_DONE`）点击“完成”时，或在完成默认桌面设置之后、正式回到桌面主界面之前。
2. **交互设计**：
   - 检查 `getMissingCorePermissions()`。
   - 若全部已具备，直接进入桌面。
   - 若有缺失，弹出诺基亚风格确认弹窗：
     - **标题**：`系统权限`
     - **内容**：`为了正常显示应用列表、双卡信号和通知消息，桌面需要获取相关运行权限。`
     - **左软键**：`允许`（触发批量请求）
     - **右软键**：`跳过`（直接进入桌面）
   - 用户点击“允许”后批量唤起系统权限申请。完成或拒绝后平滑进入桌面。

---

### 4.4 业务容错层：解冻预检、失败诊断与自愈重试（诉求二与三）

针对解冻应用（`NokiaFreezeManager.unfreeze()`）：

```
+-------------------------------------------------------------+
|                     用户点击解冻应用                        |
+-------------------------------------------------------------+
                              |
                              v
                  [ 1. 解冻前权限预检 ]
                 hasAppListPermission() ?
                   /                  \
                否 /                    \ 是
                  v                      v
        [ 弹出诺基亚权限引导框 ]      [ 执行 Shizuku pm enable ]
                  |                      |
      用户同意授权后自动重试              v
                                  [ pm enable 成功 ]
                                         |
                                         v
                           [ 2. 获取入口 Intent 尝试拉起 ]
                          getLaunchIntentForPackage(pkg)
                                   /           \
                           成功获得 /             \ 返回 null 或异常
                                  /               \
                                 v                 v
                        [ 成功拉起应用 ]   [ 3. 失败智能诊断与自愈 ]
                                                   |
                                                   v
                                          诊断是否为应用列表权限丢失？
                                            /                  \
                                         是 /                    \ 否
                                           v                      v
                                  [ 弹出恢复授权弹窗 ]       [ 提示启动入口不存在 ]
                                           |
                                 用户授权成功后
                             >>> 自动重试拉起应用 <<<
```

1. **解冻前预检**：
   - 在向 Shizuku 发送命令前，先检查应用列表权限。如果已明确丢失，直接中断命令并唤起授权，避免无效提权操作。
2. **失败诊断与自动恢复（断点续传）**：
   - 当 `pm enable` 成功但 `getLaunchIntentForPackage` 为 null 时，捕获此异常分支。
   - 自动检测权限状态：若权限已被系统撤回，立即通过回调通知 Activity 弹出诺基亚风格权限弹窗。
   - **断点续传（关键体验）**：授权回调成功时，**系统自动重新执行拉起该包名的逻辑**，无需用户再次找到该应用重新点一次解冻。
3. **针对“不再询问”的兜底**：
   - 若权限处于永久拒绝状态，弹出 `NokiaOptionsDialog`：
     - 提示：`读取应用列表权限已被禁用，导致无法启动应用。请在系统设置中允许权限。`
     - 选项：`前往设置` / `取消`。
     - 确定后直接拉起该应用的系统设置页面（`Settings.ACTION_APPLICATION_DETAILS_SETTINGS`）。

---

### 4.5 设置管理层：桌面设置增加「权限自检与修复」

在桌面设置主菜单（`NokiaSettingsGroupFragment`）中，增加：
- **菜单项**：`权限自检与修复`
- **页面内容**：
  - 应用列表权限：`[已授权]` 或 `[未授权 - 按确认键修复]`
  - 电话状态权限：`[已授权]` 或 `[未授权 - 按确认键修复]`
  - 通知访问权限：`[已授权]` 或 `[未授权 - 按确认键修复]`
  - 电池优化白名单：`[已加白]` 或 `[去设置]`
- 用户随时可以按下确认键手动对某项丢失的权限进行恢复，排查过程透明可控。

## 5. 验收标准与测试矩阵

1. **Manifest 校验**：
   - 在展锐 Android 13 设备上安装后，执行 `adb shell dumpsys package io.github.cctyl.nokia.debug | grep CTA_QUERY_ALL_PACKAGES` 能明确看到在 requested permissions 列表中。
2. **向导批量申请验证**：
   - 全新安装或清除数据后启动应用，走完按键向导，点击“完成”时，批量弹出权限申请，操作连贯无卡顿。
3. **权限丢失与自愈测试**：
   - 手动执行 `adb shell pm revoke io.github.cctyl.nokia.debug com.unisoc.permission.CTA_QUERY_ALL_PACKAGES` 模拟权限丢失。
   - 在桌面上解冻一个已冻结的应用。
   - **预期表现**：不会静默失败，系统立即弹出恢复权限弹窗，允许后立即自动拉起该应用。
4. **按键体验验证**：
   - 所有弹窗完全符合《NOKIA_DEVELOPMENT_RULES.md》规范，方向键与软键响应灵敏，无触屏强制依赖。
