# 桌面权限管理规范与解冻权限失效自愈设计方案

> 本文档规范 KeydroidX 原键桌面（及 keydroidx 生态）的权限生命周期管理，重点解决应用列表权限丢失、向导后批量申请、解冻失败自愈等问题。

---

## 1. 架构定位：模块归属决策

### 1.1 是否引入到 `keydroidx-core:nokia-common`？
**明确答复：引入到 `nokia-common` 模块，并作为生态统一权限中枢。**

#### 为什么下沉到 `nokia-common`：
1. **生态复用**：`keydroidx-music`（读写存储/音频）、`keydroidx-foucs`（无障碍/悬浮窗）、`keydroidx-browser` 等子项目均面临权限申请、被系统收回、拒绝后引导设置页等相同诉求，不应在各 App 重复造轮子。
2. **诺基亚按键机规范统一**：权限弹窗（解释为何需要该权限、去系统设置授权的引导框）必须统一采用 `NokiaOptionsDialog` / `NokiaConfirmDialog`，具有固定的 240dp 基准、按键高亮和软键栏。
3. **依赖关系**：`nokia-common` 已经统一了 `NokiaLog`、`NokiaTheme`、`NokiaDimens`、`NokiaOptionsDialog`，将 `XXPermissions` 及封装层放进 `nokia-common`，是整个生态按键体验一致的最佳保障。

## 2. 技术选型与兼容性设计

### 2.1 XXPermissions 选型与 MinSdk 19 (Android 4.4) 兼容
- **库选型**：`com.github.getActivity:XXPermissions:20.0`
- **兼容性验证**：
  - 该库 `minSdkVersion 17`，完全满足生态 `minSdk 19`（Android 4.4 KitKat）。
  - 在 Android 4.4 ~ 5.1 上，Android 尚未引入运行时权限，`XXPermissions` 在底层检测到 `SDK_INT < 23` 时直接走免申请分支，零侵入、零多余弹窗、不会崩溃。

### 2.2 展锐芯片（Unisoc / Spreadtrum）等特殊厂商 ROM 适配
- **现状**：
  - 部分展锐 4G/5G 功能机/老人机（如 FIH Q968 等）内置工信部 CTA 规范，新增了非标准的运行时权限：`com.unisoc.permission.CTA_QUERY_ALL_PACKAGES`。
  - `XXPermissions` 默认覆盖了主流大厂（小米、华为、魅族、三星等），但未覆盖展锐 CTA 特有字符串。
- **解决方案（分层适配）**：
  - 我们不绑定特定手机，但遵循“广谱适配 + 特殊平台增量探测”策略：
  ```java
  // 基础标准权限（所有手机通用）
  List<String> perms = new ArrayList<>();
  // 若系统定义了 CTA 权限（展锐等），动态追加至请求列表
  if (isPermissionDeclaredOrRequired(context, "com.unisoc.permission.CTA_QUERY_ALL_PACKAGES")) {
      perms.add("com.unisoc.permission.CTA_QUERY_ALL_PACKAGES");
  }
  ```
  - 这种设计让所有主流 Android 手机走原生与厂商通道，展锐设备走补充通道，既保持普适性又彻底消灭硬件死角。

## 3. 核心功能设计方案

### 3.1 模块结构（下沉至 `nokia-common`）
在 `io.github.cctyl.nokia.common.permission` 包下建立：
- `NokiaPermissionManager`：统一对外 API（面向调用方）。
  - `checkCorePermissions(Context)`: 检查核心权限就绪状态。
  - `requestPermissions(Activity, List<String>, PermissionCallback)`: 批量申请核心入口。
  - `showPermissionRationaleDialog(...)`: 诺基亚风格的权限用途解释弹窗（统一左右软键：左键“授权”，右键“取消”）。
  - `showPermissionSettingDialog(...)`: 用户勾选“不再询问”被永久拒绝后的引导弹窗（左键“去设置”，调用 `XXPermissions.startPermissionActivity()` 自动定位对应设置页）。

### 3.2 场景一：应用向导结束时“批量申请”
- **触发位置**：`NokiaKeyBindWizardFragment` 的最后一页（`STATE_DONE`）。
- **用户路径**：
  1. 用户完成按键录制，点击左软键【完成】；
  2. 若还有未授予的核心权限（如通知、电话状态/双卡信号、应用列表等）：
     - 弹出诺基亚风格权限告知对话框：“为正常展示电量/信号、通知及应用图标，需要申请必要权限。”
     - 用户按左软键【授权】，触发 `XXPermissions` 批量申请；
     - 系统依次弹出授权框，用户授权完毕；
  3. 若用户拒绝或全部完成，再退出向导返回桌面（`finishWizard()`），绝不阻塞用户进入桌面。

### 3.3 场景二：解冻应用失败自愈（彻底解决解冻失败）
- **触发位置**：`NokiaFreezeManager.unfreeze(packageName, callback)`
- **双重防御机制**：
  1. **解冻前预检**：
     - 若当前缺少应用列表可见性/权限，不再盲目执行 Shell 命令；
     - 主动回调宿主 Activity 弹出诺基亚提示：“解冻需要读取应用列表权限”，引导授权。
  2. **解冻后断点续传（关键自愈）**：
     - 如果 Shell 执行 `pm enable <pkg>` 成功，但 `getLaunchIntentForPackage(pkg)` 返回 null（被安全策略拦截）：
     - 诊断为应用列表权限丢失，立即捕获当前 `pendingLaunchPackage = pkg`；
     - 调起权限申请；
     - **授权回调成功后，自动触发拉起 `pendingLaunchPackage`**，用户无需二次查找和点击，体验无缝闭环！

### 3.4 场景三：桌面设置增加「权限检查与修复」
- **触发位置**：桌面设置 -> 「关于与帮助」或「系统权限自检」。
- 清单展示各项核心权限当前状态（【应用可见】、【电话与信号】、【通知监听】等）；
- 任何一项丢失时，按确认键即可一键修复或直达系统设置页。

## 4. 实施计划

1. **第 1 步：在 `keydroidx-core:nokia-common` 引入依赖与封装**
   - 在 `nokia-common/build.gradle` 引入 `com.github.getActivity:XXPermissions:20.0`。
   - 编写 `NokiaPermissionManager`。
2. **第 2 步：在 `keydroidx-launcher` 清单补全**
   - 补充 `QUERY_ALL_PACKAGES`、`com.unisoc.permission.CTA_QUERY_ALL_PACKAGES`、`GET_INSTALLED_APPS`。
3. **第 3 步：改造向导 `NokiaKeyBindWizardFragment`**
   - 串联批量申请。
4. **第 4 步：改造解冻 `NokiaFreezeManager`**
   - 增加权限检查与失败断点拉起自愈机制。
5. **第 5 步：真机联调验证**
   - 在真机（Android 13 FIH Q968）上模拟权限 revoke -> 解冻 -> 自动唤起授权 -> 自动拉起成功。
