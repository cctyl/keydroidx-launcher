# 桌面组件设置 — 界面交互设计（终版 v3）

> 本文档详细定义「桌面组件设置」界面的所有交互状态、界面展示及操作逻辑。
> 不涉及具体代码实现，仅标注各功能对应的代码模块。

---

## 一、界面层级关系

```
桌面设置 (KeydroidxDesktopSettingsFragment)
  └─ 桌面组件设置 (KeydroidxWidgetSettingsFragment)  ← 本文档核心
       ├─ 按左软键 → 弹出选项菜单（浮层，S2）
       │    ├─ 添加组件 → 组件类型选择页（S6） → 各类型编辑页
       │    ├─ 删除组件 → 进入删除模式（S3，子模式）
       │    │    └─ 按左软键 → 弹出删除子菜单：[全选] [删除已选]
       │    └─ 组件排序 → 进入排序模式（S4/S5，子模式）
       └─ 按确认键 → 进入当前光标所在组件的编辑页
```

---

## 二、状态总览

本界面共 6 种状态：

| 编号 | 状态名 | 说明 |
|------|--------|------|
| S1 | 正常浏览 | 进入该页面的默认状态，显示所有已添加的组件 |
| S2 | 左软键弹出选项菜单 | 在 S1 按下左软键后，弹出浮层菜单 |
| S3 | 删除模式 | 从 S2 菜单选择「删除组件」后进入的子模式 |
| S4 | 排序模式-光标态 | 从 S2 菜单选择「组件排序」后进入的子模式 |
| S5 | 排序模式-拎起态 | 在 S4 中按确认键拎起某行后进入 |
| S6 | 添加-类型选择 | 从 S2 菜单选择「添加组件」后进入的独立页面 |

---

## 三、各状态详细设计

### S1 — 正常浏览

**进入方式**：从桌面设置选择「桌面组件设置」进入。
**离开方式**：右软键返回桌面设置 / 左软键弹出选项菜单 / 确认键进入编辑页。

#### 界面布局

```
┌──────────────────────────────────┐
│ 桌面组件设置                       │
│ 已选 5 / 15 项                    │
├──────────────────────────────────┤
│                                  │
│  ♪  音乐播放器            [应用]    │  ← 光标在第一行
│  🌐 3g.qq.com            [网址]    │
│  📊 RAM: 2.1G / 4G      [内存]    │
│  💾 存储: 45G / 128G    [存储]    │
│  ⏱️ 今日: 2h 30m         [时长]    │
│  📅 7月30日 农历六月廿六  [日历]    │
│                                  │
│       (空列表时显示"暂无组件，       │
│        按左软键添加")               │
│                                  │
├──────────────────────────────────┤
│ 选项                            返回│
└──────────────────────────────────┘
```

#### 界面要素

- **顶部**：标题「桌面组件设置」+ 副标题「已选 X / 15 项」
- **中间列表**：每行一个组件
  - 行左侧：组件图标
  - 行中间：组件显示名称
  - 行右侧：组件类型标签（灰色小字，如 `[应用]`）
  - 超出可视区域时列表垂直滚动
- **底部软键栏**：左「选项」、中（空）、右「返回」

#### 操作

| 按键 | 行为 |
|------|------|
| 上 / 下 | 移动光标，列表自动滚动跟随 |
| 确认键 | 进入当前组件对应的**编辑页**（详见下方「确认键行为分类」） |
| 左软键 | 弹出选项菜单（→ S2） |
| 右软键 | 返回桌面设置 |

> ⚠️ **按键配对规范（DOWN/UP 成对消费）**：S1 中按确认键进入编辑页、按左软键弹 S2 菜单时，若按键 DOWN 已在 `KeydroidxDesktopActivity.dispatchKeyEvent` 本层被消费（`return true`），则**必须同步消费对应的 UP（必要时含 REPEAT）**，禁止只消费 DOWN 就放手。否则 DOWN 已被本层吞掉、UP 却透传到新页面的可点击 View，系统会在 UP 时合成 `performClick()` 触发第二次动作（典型表现：确认进入编辑页后又自动选中第一项）。实现上用 `lastHandledDownKeyCode` 记录最近一次被本层消费的 keyCode，在非 DOWN 分支对相同 keyCode 直接 `return true` 吞掉，未消费的键 DOWN 路径复位为 `KEYCODE_UNKNOWN`。

#### 确认键行为分类

不同类型的组件，确认键行为不同：

| 类型 | 确认键行为 | 说明 |
|------|-----------|------|
| 应用 | 进入应用选择界面（编辑模式） | 2 号文档 |
| 网址 | 进入网址编辑界面（编辑模式） | 3 号文档 |
| Activity快捷 | 进入 Activity 选择界面（编辑模式） | 后续文档 |
| 日历 | Toast「该组件不可编辑」 | 无可编辑属性 |
| 内存信息 | Toast「该组件不可编辑」 | 无可编辑属性 |
| 存储信息 | Toast「该组件不可编辑」 | 无可编辑属性 |
| 使用时长 | Toast「该组件不可编辑」 | 无可编辑属性 |

> **系统功能已从桌面组件系统中移除**，独立为「快捷开关」功能，详见 `docs/5-快捷开关功能设计.md`。

**Toast 交互**：

- 按确认键 → 弹出 Toast「该组件不可编辑」
- Toast 显示期间，再按确认键/方向键/返回键/右软键 → Toast 消失
- Toast 消失后恢复正常 S1 交互
- 用户可通过左软键进入 S2 → 排序/删除来调整这些组件

#### 边界情况

- 组件数量 = 0：列表区显示「暂无组件，按左软键添加」，光标不显示
- 组件数量 = 15：顶部「已选 15 / 15 项」，S2 菜单中「添加组件」灰掉

#### 对应代码模块

- Fragment：`KeydroidxWidgetSettingsFragment`（新建）
- 布局：`fragment_nokia_widget_settings.xml`（新建）

### S2 — 左软键弹出选项菜单

**进入方式**：S1 状态下按左软键。
**离开方式**：确认键 / 左软键执行选中项；右软键关闭菜单回到 S1。

#### 视觉风格（诺基亚 S60 风格）

- **菜单外观**：深色底（`#1A1A2E` 或类似深蓝灰），白色文字，圆角边框
- **选中行**：蓝色高亮背景（复刻 `bg_nokia_selected_dark`），白色文字
- **未选中行**：深色底 + 浅灰文字
- **位置**：浮层居中偏上，不铺满全屏（宽度约占 60~70%）
- **菜单外**：底层列表覆盖半透明黑色遮罩（`#000000 ~50%`），视觉上明显变暗
- **箭头光标**：选中行左侧不显示箭头（菜单项是动作，不是导航）
- 触摸点击同样生效（与现有 `KeydroidxShortcutSettingsFragment` 体验一致）

#### 焦点锁定

- 菜单弹出后，方向键光标**锁定在菜单内部**，上/下只能在菜单项之间移动
- **不可逃逸到底层列表**，不可通过左右键移出菜单
- 只有执行菜单项或按右软键关闭菜单后，才能回到 S1

#### 界面布局

```

│ 桌面组件设置                       │
│ 已选 5 / 15 项                    │
├──────────────────────────────────┤
│ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│  ← 半透明遮罩
│ ░░ ♪  音乐播放器          [应用] ░░│
│ ░░ 🌐 3g.qq.com          [网址] ░░│
│ ░░ 📊 RAM: 2.1G / 4G    [内存] ░░│
│ ░░                            ░░│
│ ░░ ┌──────────────────────┐   ░░│
│ ░░ │ 添加组件              │   ░░│  ← 浮层菜单
│ ░░ │ 删除组件              │←光标░░│    (深色底+蓝高亮)
│ ░░ │ 组件排序              │   ░░│
│ ░░ └──────────────────────┘   ░░│
│ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│
```

#### 菜单项可用性

| 菜单项 | 正常 | 已满 15 项时 | 列表为空时 | 仅 1 项时 |
|--------|------|-------------|-----------|----------|
| 添加组件 | 可选 | **灰掉不可选** | 可选 | 可选 |
| 删除组件 | 可选 | 可选 | **灰掉不可选** | 可选 |
| 组件排序 | 可选 | 可选 | **灰掉不可选** | **灰掉不可选** |

#### 操作

| 按键 | 行为 |
|------|------|
| 上 / 下 | 光标在菜单内移动 |
| 左 / 右 | 无效果（菜单为纵向列表） |
| 确认键 | 执行当前光标所在菜单项 |
| 左软键（选择） | 等同确认键 |
| 右软键（返回） | 关闭菜单，回到 S1 |

#### 各菜单项执行结果

| 菜单项 | 执行后 |
|--------|--------|
| 添加组件 | → S6（组件类型选择页） |
| 删除组件 | → S3（删除模式） |
| 组件排序 | → S4（排序模式-光标态） |

> ⚠️ **按键处理规范（接入 KeydroidxKeyBinding）**：S2 选项菜单是独立 Window（`Dialog`/`DialogFragment`），弹出后按键事件到达不了 `KeydroidxDesktopActivity`，其 `dispatchKeyEvent` 对菜单无效。菜单的按键处理**必须复用用户自定义的按键映射 `KeydroidxKeyBinding`，禁止写死 keyCode**：在 `onCreate` 中通过 `((KeydroidxDesktopActivity) requireActivity()).getKeyBinding()` 取得真实绑定实例；`setOnKeyListener` 内先 `keyBinding.resolveAction(event)` 解析成语义动作（`ACTION_SOFT_LEFT`/`ACTION_SOFT_RIGHT`/`ACTION_SELECT` 等）再分发；`KEYCODE_BACK` 由菜单单独处理（关闭菜单回到 S1）。不得直接判断 `KEYCODE_SOFT_LEFT` 等具体键码，以免漏掉 `KEYCODE_MENU` 等用户设备实际发出的键码，且需与用户在「按键绑定设置」中的自定义保持一致。

#### 界面要素

- 标题下方增加子状态标签「删除模式」
- 每行左侧出现勾选标记：
  - `[ ]` = 未勾选（灰色）
  - `[✓]` = 已勾选（绿色）
- 底部栏：左「选项」、中（空）、右「取消」

#### 操作

##### 主界面操作

| 按键 | 行为 |
|------|------|
| 上 / 下 | 移动光标 |
| 确认键 | 切换当前行的勾选状态 |
| 左软键（选项） | 弹出删除子菜单（见下方） |
| 右软键（取消） | 不删除，回到 S1 |

##### 左软键子菜单

按左软键后弹出，视觉风格与 S2 菜单相同（诺基亚 S60 浮层）：

```
┌──────────────────────────┐
│ 全选                      │
│ 删除已选（X 项）          │  ← 动态显示勾选数量
└──────────────────────────┘
```

| 菜单项 | 行为 |
|--------|------|
| 全选 | 将所有行标记为 `[✓]`。若已全选则文本变为「取消全选」，将所有行标记为 `[ ]` |
| 删除已选（X 项） | 删除所有已勾选的组件，回到 S1。若 X=0（无勾选）则此项灰掉不可选 |

子菜单中的操作：

| 按键 | 行为 |
|------|------|
| 上 / 下 | 光标在子菜单内移动 |
| 确认键 | 执行菜单项 |
| 左软键（选择） | 等同确认键 |
| 右软键（返回） | 关闭子菜单，回到 S3 主界面 |

> ⚠️ **按键处理规范（接入 KeydroidxKeyBinding）**：S3 左软键弹出的删除子菜单同样为独立 Window，与本文档 S2 菜单一致，**必须接入 `KeydroidxKeyBinding`**（`resolveAction` 解析语义动作、`KEYCODE_BACK` 单独处理），禁止写死 keyCode。

#### 边界情况

- 「删除已选」中 X=0 时：该项灰掉不可选，用户只能选「全选」或右软键取消
- 删除后列表为空：回到 S1，显示「暂无组件」空状态

#### 对应代码模块

- 在 `KeydroidxWidgetSettingsFragment` 中切换子状态实现

### S5 — 排序模式-拎起态

**进入方式**：S4 光标态按确认键拎起当前行。
**离开方式**：确认键放下 → S4；右软键放下 + 保存 → S1。

#### 界面布局

```
┌──────────────────────────────────┐
│ 桌面组件设置                       │
│ 排序模式                          │
├──────────────────────────────────┤
│                                  │
│  📊 RAM: 2.1G / 4G      [内存]    │
│  ██ 音乐播放器           [应用] ██ │  ← 拎起的行，特殊高亮
│  🌐 3g.qq.com            [网址]    │
│  💾 存储: 45G / 128G    [存储]    │
│  ⏱️ 今日: 2h 30m         [时长]    │
│  📅 7月30日 农历        [日历]    │
│                                  │
├──────────────────────────────────┤
│                                 完成│
└──────────────────────────────────┘
```

#### 界面要素

- 被拎起的行使用**独立的视觉样式**（如深色底 + 亮边框），与其他行明显区分
- 其他行无选中高亮，光标概念暂时消失
- 底部栏不变：左（空）、中（空）、右「完成」

#### 操作

| 按键 | 行为 |
|------|------|
| 上 | 拎起的行与上一行交换位置；如已到第一行则不再移动 |
| 下 | 拎起的行与下一行交换位置；如已到最后一行则不再移动 |
| 确认键 | **放下**，固定在当前位置 → 回到 S4 光标态，光标落在此行 |
| 右软键（完成） | **放下** + **保存排序** → 回到 S1 |

#### 交互细节

- 上下移动时列表自动滚动，确保拎起行始终在可视区内
- 边界不环绕
- 放下后回到 S4，用户可继续选另一行拎起

### S6 — 添加组件-类型选择

**进入方式**：S2 选项菜单选择「添加组件」。
**离开方式**：确认键选类型 → 进入对应编辑页；右软键返回 → S1。

#### Android 版本兼容性处理

> 「使用时长」组件依赖 `UsageStatsManager`（API 21+），Android 4.4 及以下不可用。
> S6 页面需根据 `Build.VERSION.SDK_INT` 动态控制「使用时长」项的可选状态。

| API 版本 | 「使用时长」项表现 |
|---------|----------------|
| ≥ 21（Android 5.0+） | 正常显示，可选 |
| < 21（Android 4.4 及以下） | **灰色显示**，文字后追加 `(需Android 5.0+)`，光标跳过此项，确认键无响应 |

```java
// KeydroidxWidgetTypePickerFragment 中构建列表时
boolean usageStatsAvailable = Build.VERSION.SDK_INT >= Build.VERSION_CODES.LOLLIPOP;
if (!usageStatsAvailable) {
    // 使用时长项设为 disabled，文字变灰，追加提示
    item.setEnabled(false);
    item.setLabel("使用时长 (需Android 5.0+)");
    item.setTextColor(0xFF666666);  // 灰色
}
```

> 焦点导航逻辑（上下键）需跳过 `enabled=false` 的项。

#### 界面要素

- 标题：「选择组件类型」
- 7 种类型，每行一个：左侧图标 + 右侧名称
- 底部栏：左（空）、中（空）、右「返回」

> ⚠️ **矢量图加载规范**：S6 页面中的类型图标（`ic_nokia_*`）均为 vector drawable。
> 布局 XML 中必须用 `app:srcCompat` 引用，**不能用 `android:src`**（API 19 崩溃）。
> 代码中加载用 `ContextCompat.getDrawable()`。详见 `安卓 4.4（API 19）矢量图崩溃修复计划.md`。

#### 操作

| 按键 | 行为 |
|------|------|
| 上 / 下 | 移动光标 |
| 确认键 | 选择类型 → 跳转对应编辑页 |
| 右软键（返回） | 回到 S1 |

> ⚠️ **按键配对规范（DOWN/UP 成对消费）**：S6 确认键选择类型跳转对应编辑页时，若确认键 DOWN 已在 `KeydroidxDesktopActivity.dispatchKeyEvent` 本层被消费，须同步消费对应 UP（含 REPEAT），禁止只消费 DOWN，否则回退到新编辑页时 UP 穿透到可点击 View 合成 `performClick()` 触发二次动作。同 S1 规范，用 `lastHandledDownKeyCode` 记录并吞掉对应 UP。

#### 选择后的跳转

| 类型 | 跳转目标 | 说明 |
|------|---------|------|
| 应用 | 应用选择列表页 | 选择已安装应用，详见 2 号文档 |
| 网址 | 网址编辑页 | 输入显示名 + 网址，详见 3 号文档 |
| 日历 | **直接添加并回 S1** | 无额外配置，添加后不可编辑 |
| Activity快捷 | Activity 选择页 | 选应用 → 选 Activity |
| 内存信息 | **直接添加并回 S1** | 无额外配置，添加后不可编辑 |
| 存储信息 | **直接添加并回 S1** | 无额外配置，添加后不可编辑 |
| 使用时长 | **直接添加并回 S1** | 无额外配置，添加后不可编辑。**API < 21 时灰色不可选** |

> 系统功能已从桌面组件类型中移除，改为独立的「快捷开关」功能，详见 5 号文档。

> 各编辑页的详细交互设计将在单独的文档中定义。

#### 对应代码模块

- Fragment：`KeydroidxWidgetTypePickerFragment`（新建）
- 布局：`fragment_nokia_widget_type_picker.xml`（新建）

## 六、确认键行为速查表

| 状态 | 确认键行为 |
|------|----------|
| S1 正常浏览 | **可编辑类型**（应用/网址/Activity）→ 进入编辑页；**不可编辑类型**（日历/内存/存储/时长）→ Toast「该组件不可编辑」 |
| S2 左软键弹出菜单 | 执行光标所在菜单项 |
| S3 删除模式 | 切换当前行勾选状态 |
| S3 删除子菜单 | 执行光标所在菜单项 |
| S4 排序-光标 | 拎起当前行 → S5 |
| S5 排序-拎起 | 放下当前行 → S4 |
| S6 类型选择 | 选择类型 → 进入对应编辑页（不可编辑类型直接添加回 S1） |
