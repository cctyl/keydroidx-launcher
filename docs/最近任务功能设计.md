# 「最近任务」功能设计文档

**状态**：已实现，真机验证通过（Android 13 / API 33，提交 `eaffa6f`）
**适用范围**：原键桌面 `ru.playsoftware.j2meloader.nokia.*`
**UI 原型**：`docs/recent-apps/prototype.html`（配 `styles.css`，一页并排 7 个 240×320 画面）
**规范依据**：`keydroidx-core/docs/NOKIA_DEVELOPMENT_RULES.md`、`reference/FEATURE_PHONE_UI_SPEC.md`（§15 选项菜单 / §16 破坏性确认 / §38 空状态）、`guide/07-dialogs.md`、`spec/typography-and-font-spec.md`

## 1 背景与目标

Android 5.0 起，普通应用读不到系统最近任务：`ActivityManager.getRecentTasks()` 被收紧（只返回自己的任务），`getAppTasks()` 同样只返回调用方自身。想在按键机上做一个「最近任务」页，必须借助 mini_shizuku 以 shell 身份读 `dumpsys activity recents`。

目标：

1. **触发范围 = 桌面主界面 + 功能表**，且路径最短（一个物理键一步到位）；
2. 卡片式展示最近任务，**确认键把应用恢复到它之前的界面（恢复，不是重启）**；
3. 具备清理后台能力，并与既有「后台管理」共用一套保护名单；
4. 状态齐备：加载 / 空 / 未激活三态都必须有设计，未激活态必须可操作。

**非目标（硬约束）**：不展示真实缩略图——系统 Recents 的 `TaskSnapshot` 需要 `CAPTURE_TASK_SNAPSHOTS` 等系统级权限，第三方应用也不可能截取别家应用的当前画面。卡片只能用「应用图标 + 应用名 + 最近时间」表达。

## 2 方案选型

最初有两个想法，最终**合并采用**：

| 方案 | 内容 | 结论 |
|---|---|---|
| 方案一 | 升级桌面「后台管理」小组件，让它显示最近任务，选择后跳转 | 不单独采用（组件只在桌面，覆盖不到功能表；单行文字放不下卡片网格） |
| 方案二 | 绑定按键弹出全屏卡片页，可清理后台 | **主方案** |
| 合并 | 组件点击也进入同一个页面，两入口共用一套 UI | **采用** |

选方案二为主的三条理由：

1. **覆盖范围**：桌面与功能表都在同一个 `KeydroidxDesktopActivity` 内，按键动作在 Activity 层生效 → 天然覆盖两处；而组件只在桌面，功能表还得另开入口。
2. **功能机范式**：规范 RULE 01/17 要求「物理键优先、一键一能、少层级」。专用键直接出卡片，比「回桌面 → 找组件 → 点」短。
3. **界面空间**：卡片列表需要整屏（标题 + 网格 + 软键栏），弹窗或组件单行都撑不住。

组件依然保留为桌面快捷入口（点击进入同一页），不浪费既有入口。

## 3 入口与交互总览

### 3.1 两个入口，一套 UI

1. **按键动作**：`KeydroidxKeyBinding.ACTION_RECENT_APPS`（第 10 个动作，**默认未绑定**，用户在按键绑定/向导里指定键即可）。已停留在该页时重复按键被忽略，避免重复入栈。
2. **桌面组件**：`KeydroidxWidgetItem.TYPE_BG_MANAGER`（「后台管理」组件）点击进入该页；原「运行 / 受保护」两页签的后台管理页改从本页选项菜单进入。

### 3.2 页面结构（240×320 基准）

```
┌─────────────── 240 ───────────────┐
│ 最近任务                  实时     │ ← 标题 + 数据模式徽标（绿=实时 / 红=未激活）
│ 未保护 4 · 已保护 1      按 0 键清理│ ← 摘要行（caption 9sp）
├───────────────────────────────────┤
│ ┌─────────┐  ┌─────────┐          │
│ │  LocalSend│ │ 音乐 🛡 │          │ ← 卡片 56dp；盾牌=已保护
│ └─────────┘  └─────────┘          │
│ ┌─────────┐  ┌─────────┐          │
│ │  Alook  │  │ 原键鼠标 │          │
│ └─────────┘  └─────────┘          │
├───────────────────────────────────┤
│ 选项          最近任务        退出 │ ← 软键栏（无高亮，空栏置空文字不用 GONE）
└───────────────────────────────────┘
```

- **2 列卡片**：卡片高 56dp、圆角 6dp；应用图标 26dp、应用名 12sp（超长省略）、时间 9sp、保护盾牌角标 11dp。
- 卡片底色取 `KeydroidxTheme.cardBgColor`，焦点态用 `KeydroidxTheme.createSelectionDrawable()`；状态色沿用兄弟页面 `KeydroidxBackgroundManagerFragment` 的同一组字面量，避免同类状态两种颜色。
- 尺寸一律走 `KeydroidxDimens.dp()`，图标走 `KeydroidxIcons`，≤13sp 不加粗（点阵字体加粗会糊）。

## 4 按键与焦点

| 按键 | 行为 |
|---|---|
| 方向键 | 焦点循环移动：左右 ±1、上下 ±列数（2），越界绕回（焦点永不落在无效格） |
| 确认键 | **恢复该应用到前台**（见 §7） |
| 左软键 | 选项菜单（数据源可用但列表为空时置空文字，视图仍占位） |
| 右软键 / 返回键 | 退出，回桌面 |
| **数字键 0** | **一键清理未保护后台（无二次确认）** |

**选项菜单**（统一走 `KeydroidxOptionsDialog`，`OptionItem` 模型）：

| 项 | 出现条件 |
|---|---|
| 打开应用 | 有焦点卡片 |
| 保护此应用 / 取消保护 | 有焦点卡片（按当前状态翻转图标与文案） |
| 后台管理 | 恒有（进入原「运行 / 受保护」页） |
| 刷新列表 | 恒有 |
| 清理此任务 | 有焦点卡片且数据源可用 |
| 清理全部后台 | 有焦点卡片且数据源可用 |
| 激活 mini_shizuku | 仅未激活态（此时不显示上面各项） |

进入页面必须处理规范里的「首个方向键被吞」：根视图 `focusable` + `focusableInTouchMode` 并立即 `requestFocus()`（`post` 兜底），非业务 `ScrollView` 设 `focusable=false`。

## 5 数据源与可用性

### 5.1 两条通道

| 版本 | 数据来源 | 权限 / 依赖 | 徽标 | 时间信息 |
|---|---|---|---|---|
| Android 4.4（API < 21） | `ActivityManager.getRecentTasks()` | `GET_TASKS`（normal 级，安装即授予） | 实时 | 无（`getRecentTasks` 不提供时间，卡片不显示时间行） |
| Android 5.0+ 且 mini_shizuku 在线 | shell 执行 `dumpsys activity recents` 解析 | mini_shizuku（TCP 10500） | 实时 | 有 |
| Android 5.0+ 未激活 | — | — | 未激活 | — |

判定逻辑（`KeydroidxRecentTasksHelper.getMode()`）：

```java
if (SDK_INT < LOLLIPOP) return MODE_REAL_TASK;              // 4.4 直接可用
if (KeydroidxBgManagerHelper.isShizukuActivated()) return MODE_REAL_TASK;
return MODE_UNAVAILABLE;                                     // 5.0+ 未激活：不给用
```

**所以「未激活」只可能出现在 5.0+ 设备上**；4.4 用户永远看不到它（`KeydroidxBgManagerHelper.needsShizuku()` 在 4.4 返回 false，"已激活"恒为 true）。

### 5.2 刻意不做降级

5.0+ 未激活 mini_shizuku 时**不提供**「最近使用」（`UsageStatsManager`）之类的近似列表：

- 它只是「历史打开记录」，**不代表任务还在**，点进去只能冷启动，属于误导；
- 它与桌面组件的后台计数口径完全对不上，会让用户看到互相矛盾的数字。

因此未激活即返回空列表，UI 显示未激活态并给出激活入口（空态按钮 + 左软键选项内直达）。相关代码与权限已删除：`collectViaUsageStats()`、`hasUsageAccess()`、`MODE_USAGE_FALLBACK`、Manifest 的 `PACKAGE_USAGE_STATS`。（「使用时长」桌面组件用的是 `SystemClock.elapsedRealtime()`，不依赖该权限。）

### 5.3 线程模型

`enumerate()` 内含 shell（TCP）与 PackageManager（重 IPC）调用，**必须在后台线程执行**；页面进入时先 `KeydroidxBgManagerHelper.probeShizukuSync()` 刷新状态缓存（主线程做 TCP 会抛 `NetworkOnMainThreadException`），结果回主线程渲染。

### 5.4 dumpsys 解析要点

按 `Task{...}` / `TaskRecord{...}` 切块，块内包名优先取 `A=<uid>:<pkg>`，其次取 `cmp=` / `realActivity=` 的组件包名；时间取 `lastActiveTime|lastTimeMoved|lastUsedTime`，按「落在哪个时间基区间」自动判定 uptime / 墙上时钟（两者都不成立按未知处理）。解析不到内容时宁可显示空列表，也不伪造数据。

### 5.5 挂机 jar 条目

挂机中的 J2ME 应用作为独立条目**固定置顶**（唯一能确定"还活着"的条目，且自身进程可枚举、不依赖任何特权），key 形如 `midlet:<appPath>`；恢复时复用既有启动入口 `Config.startApp(...)`，清理时走广播 `ACTION_DESTROY_MIDLET` 让 `:midlet` 进程优雅销毁（**严禁** `force-stop`/`killBackgroundProcesses`，它们作用于整个包，会连桌面主进程一起杀）。

## 7 恢复语义（不重启）

确认键把目标任务恢复到前台，做法是**重新下发该应用的启动 Intent**：

```java
launch.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK | Intent.FLAG_ACTIVITY_RESET_TASK_IF_NEEDED);
ctx.startActivity(launch);
```

系统按 taskAffinity 找到已存在的任务栈并把它拉到前台，栈顶 Activity 只走 `onResume`（不重建）→ 用户回到该应用之前停留的界面；任务确实已被系统回收时才会冷启动——这与系统桌面点击图标的行为一致，无法规避。

**刻意不用 `ActivityManager.moveTaskToFront()`**：它在 Android 10+ 对第三方应用被静默限制（既可能无异常也不产生位移），无法据此判断失败并降级，反而会吞掉本可成功的恢复动作。

## 8 清理与保护名单

### 8.1 三档清理

| 操作 | 范围 | 二次确认 | 保护名单 |
|---|---|---|---|
| **数字键 0** | 本页列出的**未保护**任务 | **无** | 跳过已保护 |
| 选项 · 清理全部后台 | 同上 | **无** | 跳过已保护 |
| 选项 · 清理此任务 | 单个应用（**可以是已保护的**） | **有** | **不受限** |

保护名单语义：保护只挡**批量清理**（0 键 / 清理全部）；「清理此任务」是用户对单个应用的显式操作，仍然生效（确认弹窗会额外提示"该应用在保护名单中，本次为手动清理"）。

> **确认策略（已定稿）**：批量清理（0 键 / 清理全部后台）**不做二次确认**，与「后台管理」页 0 键的既有行为保持一致——它们只清未保护项，已有保护名单兜底；只有**单项手动清理**（可作用于已保护应用，无"批量"预期）弹确认。

「清理此任务」的确认按 `FEATURE_PHONE_UI_SPEC` §16：更安全的「取消」在左、破坏性「清理」在右；确认键与左软键等效，因此误按确认键只会取消。

### 8.2 实现方式

清理对象是**本页列出的任务**，而不是「正在运行的进程」：

- 5.0+（mini_shizuku 在线）：逐个 `am force-stop <pkg>`。`force-stop` 会**同时移除该应用的任务记录**，卡片才会真正消失——若改用 `clearBackgroundTasks()`（它只枚举存活进程），会出现"按了 0 键卡片还在"的假象。
- 4.4：`ActivityManager.killBackgroundProcesses(pkg)`。
- 挂机 jar：广播销毁（见 §5.5）。

保护名单持久化在 `KeydroidxSettingsStorage.getProtectedPackages()/setProtectedPackages()`，与「后台管理」页**共用同一份**；两个页面均在 `onResume` 重新读取，互改立即生效、重启不丢。

## 9 口径一致性（本次踩坑的根源）

「桌面组件显示 N 个后台」与「最近任务页显示 M 条」是两套语义，但**必须自洽**：

| | 桌面组件「N 个后台」 | 最近任务页 |
|---|---|---|
| 数据源 | `ps -A` 数**此刻存活的进程** | `dumpsys activity recents` 数**任务记录** |
| 代码 | `KeydroidxBgManagerHelper.countBackgroundProcesses()` | `KeydroidxRecentTasksHelper.enumerate()` |

为让两者一致，做了四件事：

1. **列表只展示进程仍存活的任务**（`buildTasks()` 内按 `getAlivePackages()` 过滤）。原因：`am force-stop`（含本应用清理、系统查杀）**只杀进程、不删任务记录**，被清掉的应用会以 `sz=0` 空壳继续留在系统 recents 里；不过滤就会出现「桌面后台 1、最近任务 4」的"尸体卡"。存活判据与后台计数完全同一套（5.0+ `ps -A`、4.4 `getRunningAppProcesses`）；**无法判断时返回 `null` 并跳过过滤**，避免误杀有效条目。
2. **「已清理」标记会被存活校对撤销**（`CLEARED_PKGS`）。历史 bug：标记只加不撤，用户从图标重启应用后本进程感知不到，该应用被**永久隐藏**（实测 LocalSend 再也不出现）；现在枚举时若探测到进程复活即撤销标记。
3. **后台计数排除当前默认输入法包**（`Settings.Secure.DEFAULT_INPUT_METHOD` 取包名）。用户安装的第三方输入法不带 `FLAG_SYSTEM`，`isSystemApp()` 拦不住，而输入法进程常驻内存，会让组件数字虚高（实测组件 2、页面 1，差的正是搜狗输入法）。
4. 两者都排除桌面自身（含 `:midlet` 等子进程）。

**仍可能不等的边界（属正常语义差异）**：进程活着但从未打开过界面（纯服务进程）只进组件计数；任务记录还在但进程已死则两边都不显示。

## 10 关键坑与决策记录

| 现象 | 根因 | 处理 |
|---|---|---|
| LocalSend 明明在跑却不在列表 | `CLEARED_PKGS` 标记只加不撤，重启后仍被隐藏 | 枚举时用真实存活集合校对，活着即撤销标记 |
| 组件显示 2、页面显示 1 | 组件把常驻的搜索输入法算成后台 | 后台枚举排除默认输入法包 |
| 组件显示 1、页面显示 4 | `force-stop` 残留 `sz=0` 空壳任务记录被当条目 | 真实任务模式按进程存活过滤 |
| 0 键清理后卡片不消失 | 原用 `clearBackgroundTasks()`，它只枚举存活进程，清不到任务记录 | 改为逐个 `am force-stop` 列表中的目标任务 |
| 未激活时列表"看起来还能用" | 曾有 UsageStats 降级通道 | 直接移除，未激活即不可用 |

## 12 验收与实测

- 构建：`.\gradlew.bat assembleOpenDebug`、`:app:lintOpenDebug` 均通过。
- 真机（Android 13，`192.168.1.4:5555`）：
  - 组件「N 个后台」与页面条目数一致（实测 1 = 1）；
  - 0 键清理（`目标=2 成功=2`）后列表只剩受保护条目，空壳卡不出现；
  - 从图标重启应用后再进页面，该应用自动回到列表（日志：`已清理包检测到重新启动，撤销标记`）；
  - 停掉 mini_shizuku（`kill` + 端口 10500 不再监听）→ 页面显示未激活态，徽标转红。
- 4.4 通道（`getRecentTasks`）本轮未做真机回归，需要时在 4.4 设备上补测（预期：无需激活，徽标恒为「实时」，卡片无时间行）。

## 13 已知差异与后续

1. **批量清理不做二次确认（已定稿，A 方案）**：0 键与「清理全部后台」直接执行；只有「清理此任务」弹确认。原型 Screen 04 已同步改为「清理此任务」的确认画面（不再画批量清理的确认）。
2. **按键默认未绑定**：`ACTION_RECENT_APPS` 默认不占用任何键，需用户在按键绑定/首次向导里自行指定。
3. **真实缩略图不做**：见 §1 非目标说明。
4. **4.4 无「最近时间」**：`getRecentTasks` 不提供时间戳，卡片只显示图标与应用名。
