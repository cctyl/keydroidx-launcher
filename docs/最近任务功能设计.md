## 1 演进背景与核心原则

### 1.1 历史演进：为什么彻底放弃「最近任务」转向「后台管理」？

在早期版本中，曾尝试模仿现代触屏手机的「最近任务」模式（基于 `dumpsys activity recents` 读取任务栈历史，并以 2 列卡片展示）。在实际真机（按键机 Q968，Android 13）体验中暴露了三大根本性缺陷：

1. **语义虚假（尸体卡片）**：
   `dumpsys activity recents` 记录的是**用户打开过的历史记录**，而不是「哪些进程在后台活着」。应用被强杀后，系统会留着 `sz=0` 的空壳历史记录。桌面后台显示 1 个，进去却列出 4 个早已死亡的应用，严重误导用户；
2. **UI 范式水土不服**：
   在 240×320（sw376dp）等小屏幕功能机上，2 列卡片极其局促，应用名称被迫严重截断，右上角的触屏关闭叉号（`×`）不仅占位而且在物理按键机上违和、无法点击；
3. **缺少真实系统物理指标**：
   极客按键机用户打开后台管理的核心诉求是：**看内存还剩多少、哪个应用在偷跑 CPU、应用运行了多久、能否干净清理**。

**重构决议**：彻底删除 `KeydroidxRecentTasksFragment` 与 `KeydroidxRecentTasksHelper`，全面重构为**基于纯物理存活进程的「后台管理（KeydroidxBgManager）」**。

### 1.2 核心设计原则

1. **只列真活进程**：只展示当前真正在系统后台消耗物理资源（内存/CPU）的存活进程与挂机 JAR 应用；进程一旦死亡立即从列表消失；
2. **真实系统物理指标**：
   - 顶部系统 RAM 仪表盘（可用量/总量 + 诺基亚蓝刻度条 + 后台总 CPU）；
   - 每行展示真实物理内存（PSS MB）、运行时长（⏱）与 CPU 占用百分比；
3. **融合 J2ME 与安卓生态**：百宝箱中挂起的 JAR 应用（在 `:midlet` 子进程中运行）与安卓原生应用在视觉上无缝融合，并支持精准物理内存统计与优雅退出；
4. **纯正物理按键操控**：
   - 方向键上下单列循环移动焦点，高亮整行深蓝底色，内存胶囊白底深蓝字反色高对比；
   - 确认键一键唤回前台续跑；
   - 数字键 **5** 就地清理当前高亮任务；
   - 数字键 **0** 一键批量清理所有未保护后台。

## 3 底层指标采集与进程模型

### 3.1 存活进程与物理指标解析流程

```
[后台线程]
   │
   ├─► 1. dumpsys activity processes (shell / mini_shizuku)
   │        │
   │        ├─► 正则锚点匹配: ^\s*\*(?:APP|PERS)\*\s+UID\s+\d+\s+ProcessRecord\{[0-9a-fA-F]+\s+(\d+):([^/]+)/
   │        │   (忽略尾部 bare PID #N: 汇总，防止空块覆盖)
   │        │
   │        ├─► 块内跨行提取:
   │        │     - lastPss=XXMB  (物理内存 PSS)
   │        │     - lastRss=XXMB  (常驻内存 RSS)
   │        │     - startUptimeTime=-XhYmZs  (启动距今运行时间)
   │        │
   │        └─► 排除桌面主进程 (ctx.getPackageName()) 与默认输入法 (Secure.DEFAULT_INPUT_METHOD)
   │
   ├─► 2. dumpsys cpuinfo (shell / mini_shizuku)
   │        │
   │        └─► 解析每个 PID 的滚动均值百分比；未上榜的存活进程记为 0%
   │
   └─► 3. 关联 MidletStateStore (挂机 JAR 跨进程状态)
            │
            ├─► 优先从 dumpsys details 中读取 :midlet 子进程指标
            └─► 降级机制：调用 ActivityManager.getProcessMemoryInfo(new int[]{midletPid})
```

### 3.2 百宝箱挂机 JAR 应用（`:midlet` 子进程）完整支持

- **物理载体**：JAR 应用在独立的 `:midlet` 子进程（`io.github.cctyl.nokia.debug:midlet`）中运行，由 `MicroActivity` 承载。
- **状态存储与双保险采集**：
  1. `MidletStateStore` 原子写入 `pid` 与 `startTime`（毫秒时间戳）；
  2. 优先从 `dumpsys activity processes` 中提取该子进程块的 `lastPss` 和 `uptime`；
  3. 若处于 Android 4.4 或 dumpsys 未命中，因 `:midlet` 与主进程同属一个 UID，直接通过 Android 原生 `ActivityManager.getProcessMemoryInfo(new int[]{pid})` 获取精准物理 PSS，结合 `startTime` 计算运行时长。
- **销毁语义（绝不误杀桌面）**：
  普通安卓应用调用 `am force-stop <pkg>` 强杀；挂机 JAR 应用**严禁调用 force-stop**（否则整个桌面会被连带杀死）。清理挂机 JAR 时，发送显式广播 `ACTION_DESTROY_MIDLET` 到 `:midlet` 进程，由 `KeydroidxMidletControlReceiver` 驱动优雅退出：
  `END 键模拟 -> destroyApp(true) -> 清除状态文件 -> Process.killProcess(midletPid)`。

## 4 按键交互与操控语义

| 物理按键 / 动作 | 交互行为 | 说明 |
|---|---|---|
| **方向键 上/下** | 焦点在单列列表中上下循环移动 | 循环绕回，焦点永不落空；选中项整行深蓝高亮，内存胶囊反色 |
| **确认键（SELECT）** | **恢复/切换至目标应用前台** | 普通应用通过 `Intent.FLAG_ACTIVITY_NEW_TASK` 拉起；挂机 JAR 调用 `Config.startApp(...)` 唤回 `MicroActivity` 画面续跑 |
| **数字键 5** | **就地清理当前高亮任务** | **无二次确认**，就地清理并从列表移除，RAM 仪表盘实时回升 |
| **数字键 0** | **一键批量清理所有未保护后台** | **无二次确认**，跳过带有 `🛡️ 已保护` 的项 |
| **左软键（SOFT_LEFT）** | 打开选项菜单 | 列表为空时隐藏左软键文字 |
| **右软键（SOFT_RIGHT）/ 返回键** | 退出，返回上一层待机屏 | 待机屏组件数字与实际存活状态保持完全同步 |

### 4.1 选项菜单规范（`KeydroidxOptionsDialog`）

- **打开应用**：唤回前台；
- **保护此应用 / 取消保护**：切换当前高亮应用的保护状态。保护名单持久化于 `KeydroidxSettingsStorage`，跨重启有效；
- **刷新列表**：重新触发进程枚举与资源采样；
- **清理此任务**：弹二次确认框（左软键「取消」/ 确认键等价取消，右软键「清理」执行破坏性操作）；受保护应用手动单清时会在确认框多出一行说明；
- **清理全部任务**：等价于数字键 0；
- **激活 mini_shizuku**：仅在未激活态时显示。

## 5 关键踩坑与防范规范

1. **展锐（Unisoc）硬件看门狗超时崩溃（Kernel Panic）防范**：
   在息屏或锁屏状态下，展锐低端芯片的 SurfaceFlinger 极易发生 Binder 阻塞。严禁连续执行 `screencap` 与 `uiautomator dump`，否则会触发 `UnisocWatchdog` 判定系统 Hung 死并强制重启设备。
2. **`dumpsys activity processes` 汇总段覆盖 bug**：
   系统输出的尾部包含裸 `PID #N:` 摘要行。正则表达式必须严格锚定首行标记 `^\s*\*(?:APP|PERS)\*`，防止空块解析覆盖已提取出的详情数据。
3. **输入法常驻进程过滤**：
   第三方输入法（如搜狗输入法）无 `FLAG_SYSTEM`，但作为常驻服务不应计入用户后台。必须通过 `Settings.Secure.DEFAULT_INPUT_METHOD` 获取当前默认输入法包名并在统计与列表中统一过滤，确保桌面组件计数与页面条目口径严格一致（1 = 1）。
4. **加载中 UI 闪烁消除**：
   页面在后台异步刷新或对齐时，顶部 RAM 仪表盘**严禁置为 `GONE`**，必须保持常驻显示，仅更新数据，彻底杜绝瞬间消失再出现的跳动闪烁。
5. **mini_shizuku 服务端白名单**：
   Root 服务端必须登记 `dumpsys activity processes` 与 `dumpsys cpuinfo` 模板，否则在 root 模式下命令会被拒绝拦截导致数据为空。
