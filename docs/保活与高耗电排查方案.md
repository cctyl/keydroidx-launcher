# 保活与高耗电（频繁阻止系统休眠）排查方案

> 状态：**待审核**（尚未做任何代码改动）
> 设备：FIH Q968 / Android 13（SDK 33）/ 展锐 Unisoc（内核线程 `sprd-*`）/ RAM 2.5GB + zram 1.5GB
> 应用：`io.github.cctyl.nokia.debug`（uid 10173），versionName 1.2-open，装机时间 2026-09-01 16:32:59
> 排查时间：2026-09-01 17:30 ~ 18:10

## 零、结论速览

两个现象**根因不同**，且都与"电量策略"直觉相反：

| 现象 | 真凶 | 前台服务能否挡住 |
|---|---|---|
| 锁屏/后台被杀 | `UnisocWatchdog.killBackground_onlyLargeRam` —— 内存吃紧时杀 RSS+swap 最大的第三方后台进程 | **不能**（有实测日志） |
| "频繁阻止系统休眠" | `NokiaDesktopKeepAliveService` 持有的 `PARTIAL_WAKE_LOCK`（8.15 小时） | 无关 —— 前台服务本身不阻止休眠，只有 wakelock 会 |

因此正确方向是：**降内存（治本）+ 不持锁的前台服务（治标）+ 通知权限/白名单引导（可感知）**。

## 二、根因二："频繁阻止系统休眠"来自 PARTIAL_WAKE_LOCK

`adb shell dumpsys batterystats --checkin | grep 10173`：

```
9,10173,l,pr,"io.github.cctyl.nokia.debug",140050,81710,284810,21,2,0
9,10173,l,apk,0,io.github.cctyl.nokia.debug,ru.playsoftware.j2meloader.nokia.NokiaDesktopKeepAliveService,29359032,4,6
9,10173,l,fg,8113349,56
9,10173,l,fgs,3035623,6
9,10173,l,cpu,227445,117182,0
```

- `apk` 行：wakelock tag = `ru.playsoftware.j2meloader.nokia.NokiaDesktopKeepAliveService`，
  累计 **29359032 ms ≈ 8.15 小时**，获取 4 次（平均每次约 2 小时），统计窗口约 15 小时。
- `cpu` 行：user 227s + system 117s，CPU 本身**并不高**。
- 主进程源码（`app/src/main/java`）**没有任何 `newWakeLock`** 调用点 —— 这段持锁来自
  §1.2 那个未提交/已回退的保活服务。

**这就是系统判"频繁阻止系统休眠"的唯一依据。前台服务提升的是进程优先级（adj），不会阻止
CPU 休眠；持 `PARTIAL_WAKE_LOCK` 才会。** 二者必须解耦。

### 2.1 追加：通知权限根本没授予

```
adb shell pm dump io.github.cctyl.nokia.debug | grep POST_NOTIFICATIONS
  android.permission.POST_NOTIFICATIONS: granted=false
```

Android 13（API 33）上通知权限默认拒绝 → 保活通知**根本没显示出来**，用户既看不到、也无法
在系统里管理它，FGS 对用户完全不可见。

## 三、方案

### A. 降内存（治本，优先级最高）

目标：后台 `rssswap` 从 ~63MB 压到 28MB 量级（低于同轮回收里 bilibili 的水平），让
`killBackground_onlyLargeRam` 的排序不再选中我们。

| # | 改动 | 位置 |
|---|---|---|
| A1 | 去掉 `android:largeHeap="true"`，堆上限从 ~512MB 降到 ~128–192MB，GC 更积极、RSS/SwapPss 明显下降 | `app/src/main/AndroidManifest.xml:76` |
| A2 | 新增 `onTrimMemory()`：`TRIM_MEMORY_UI_HIDDEN` / `TRIM_MEMORY_BACKGROUND` 时清 `NokiaAppIconCache` 内存 LruCache（192 条 Drawable）、壁纸与 GL 缓存 | `NokiaDesktopActivity` / `EmulatorApplication` |
| A3 | `TRIM_MEMORY_COMPLETE` 深度清理（各 Fragment 可重建缓存），并补 `onLowMemory()` 兜底 | 同上 |
| A4 | `NokiaLockServer` 生命周期从 onCreate/onDestroy 迁移到 onStart/onStop —— 当前退后台仍占着一个 ServerSocket 线程 + 端口 | `NokiaDesktopActivity.java:80`、`:358` |

风险与取舍见 §四.1。

### B. 保活通知（不耗电版）

新建主进程 `NokiaDesktopKeepAliveService`，`foregroundServiceType="specialUse"`。

1. **绝不 acquire `WakeLock` / `WifiLock`** —— 与上一版最关键的差别。去掉后 §二 那 8.15 小时
   归零，"阻止休眠"告警随之消失。
2. 服务本体极轻：不加载任何模拟器类、不碰 Room、不启额外线程；`onStartCommand` 里只
   `startForeground()` 后立刻返回 `START_STICKY`。
3. 生命周期：`NokiaDesktopActivity.onStop()` 起、`onStart()` 停（亮屏时不无谓常驻）；
   走 `ContextCompat.startForegroundService` + try/catch（Android 12+ 后台 FGS 限制）。
4. 通知：独立 channel（`IMPORTANCE_LOW`、`setShowBadge(false)`）+ `setOngoing(true)` +
   点击回桌面 + 一个「停止保活」action（避免"甩不掉的通知"观感）。
5. **补 `POST_NOTIFICATIONS` 运行时申请**：API 33+ 首次进入桌面时引导授权；未授权则保活降级
   并给出提示，否则重演"通知看不见"。
6. 桌面设置新增「电池优化白名单」开关 → `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`
   （+ manifest 补 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 声明），并说明"锁屏后仍可能被
   系统回收"。

> 预期效果：对抗常规 lmkd / AMS 后台回收有效；**对 `UnisocWatchdog` 的 `onlyLargeRam` 无效**，
> 那部分只能靠 A 线降内存解决。这是本方案与上一版最大的认知差异。

### C. 挂机服务的锁一并收敛

同一个耗电告警按**包**统计，`:midlet` 进程持的锁也算到我们头上。
`NokiaMidletKeepAliveService.java:153-181` 当前**无条件**获取 `PARTIAL_WAKE_LOCK` +
`WIFI_MODE_FULL_HIGH_PERF`，挂机多久就"阻止休眠"多久。

1. wakelock 改为「默认关 / 设置里开关」，或超时自动释放（如 10 分钟无数据活动即释放）。
2. `WIFI_MODE_FULL_HIGH_PERF` → `WIFI_MODE_FULL`（前者让 WiFi 芯片保持高性能，计入耗电）。
3. 仅在灭屏期间持锁，`ACTION_SCREEN_ON` 时立即释放。

## 四、待拍板事项

1. **`largeHeap="true"` 能否去掉？**（A1，降内存最有效的一步）
   影响：可能波及跑 jar 的 `:midlet` 进程（大游戏）。`largeHeap` 是 `<application>` 级、跨进程
   生效，无法只对某个进程设置。可选：
   - 整体去掉（最省内存，需真机验证功能表/百宝箱/大 jar 不 OOM）
   - 仅 `dev`/`open` flavor 去掉，`play` 保留
   - 加「低内存模式」开关，由用户取舍

2. **常驻通知要不要带「停止保活」按钮？**

3. **挂机 wakelock 是「默认关」还是「超时自动释放」？**

4. **确认真实痛点**：桌面被杀对 Launcher 是可恢复的（按 Home 会重建）。你真正痛的是——
   - (a) 回桌面慢 / 桌面状态丢失 → 方向应叠加**冷启动加速 + 状态持久化**，而非保活
   - (b) 锁屏期间有东西必须持续跑（挂机 jar、通知监听等）→ 按 B/C 线做

## 五、验收标准

| 项 | 命令 | 期望 |
|---|---|---|
| wakelock 归零 | `adb shell dumpsys batterystats --checkin \| grep 10173` | `apk` 行 wakelock 时长为 0 或大幅下降（目标 < 分钟级） |
| 不再被看门狗杀 | `adb shell logcat -b events \| grep UnisocWatchdog` | 退后台后 `try to kill:io.github.cctyl.nokia.debug` 之后不再跟 `processJavaDied`；若仍出现，检查 `rssswap=` 是否已降到 28MB 量级 |
| 进程存活 | 锁屏 10 分钟后 `adb shell ps -A \| grep nokia` | 进程仍在 |
| 通知可见 | `adb shell dumpsys notification --noredact \| grep nokia` | 出现常驻通知；`POST_NOTIFICATIONS granted=true` |
| 内存下降 | 退后台 5 分钟后 `adb shell dumpsys meminfo io.github.cctyl.nokia.debug` | PSS 目标 < 60MB，SwapPss 明显下降 |
