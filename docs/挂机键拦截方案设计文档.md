# 挂机键（ENDCALL）拦截方案设计文档

## 1. 需求背景

本应用是诺基亚风格安卓桌面 Launcher（`NokiaDesktopActivity`），运行在 Android 4.4（API 19）设备上。
用户按下物理挂机键（红色挂断键，`KEYCODE_ENDCALL`，keyCode=6）时，系统会退出本应用回到默认桌面，
即使已将本应用设为默认桌面也不生效。目标是：**按下挂机键后不能退出本应用**。

## 2. 原理分析：为什么 App 层拦截不到挂机键

### 2.1 Android 按键事件分发流程

```
内核 input 设备
  → EventHub 读取原始事件
    → InputReader 解析为 KeyEvent
      → InputDispatcher 分发
        → PhoneWindowManager.interceptKeyBeforeQueueing()  ← 系统级拦截（第一道）
          → 若 ACTION_PASS_TO_USER 被清除 → 事件不传递给 App
          → 若保留 → PhoneWindowManager.interceptKeyBeforeDispatching() ← 系统级拦截（第二道）
            → Activity.dispatchKeyEvent() ← App 层（我们代码在这里）
```

### 2.2 PhoneWindowManager 对 ENDCALL 的处理

在 Android 4.4 源码 `frameworks/base/policy/src/com/android/internal/policy/impl/PhoneWindowManager.java` 中：

```java
case KeyEvent.KEYCODE_ENDCALL: {
    result &= ~ACTION_PASS_TO_USER;   // ★ 关键行：清除 PASS_TO_USER 标志
    if (down) {
        ITelephony telephonyService = getTelephonyService();
        boolean hungUp = false;
        if (telephonyService != null) {
            hungUp = telephonyService.endCall();  // 先尝试挂断电话
        }
        interceptPowerKeyDown(!isScreenOn || hungUp);
    } else {
        if (interceptPowerKeyUp(canceled)) {
            // 行为1：END_BUTTON_BEHAVIOR_HOME → 执行 goHome()
            if ((mEndcallBehavior & Settings.System.END_BUTTON_BEHAVIOR_HOME) != 0) {
                if (goHome()) { break; }
            }
            // 行为2：END_BUTTON_BEHAVIOR_SLEEP → 息屏
            if ((mEndcallBehavior & Settings.System.END_BUTTON_BEHAVIOR_SLEEP) != 0) {
                result = (result & ~ACTION_POKE_USER_ACTIVITY) | ACTION_GO_TO_SLEEP;
            }
        }
    }
    break;
}
```

**`result &= ~ACTION_PASS_TO_USER`** 这一行意味着：

- 挂机键事件**永远不会传递到 App 层**的 `dispatchKeyEvent()` / `onKeyDown()` / `onKeyUp()`
- 我们的 `NokiaDesktopActivity.dispatchKeyEvent()` 根本收不到 `KEYCODE_ENDCALL`
- 所以在 App 层重写 `dispatchKeyEvent` 或 `onKeyDown` 拦截挂机键是**不可能的**
- 系统在 InputDispatcher 层就把事件截断了，然后根据 `Settings.System.END_BUTTON_BEHAVIOR` 决定执行 `goHome()` 还是 `GO_TO_SLEEP`

### 2.3 END_BUTTON_BEHAVIOR 设置

```java
// frameworks/base/core/java/android/provider/Settings.java
public static final String END_BUTTON_BEHAVIOR = "end_button_behavior";
public static final int END_BUTTON_BEHAVIOR_HOME = 0x1;   // 按挂机键 → 回桌面
public static final int END_BUTTON_BEHAVIOR_SLEEP = 0x2;  // 按挂机键 → 息屏
public static final int END_BUTTON_BEHAVIOR_DEFAULT = END_BUTTON_BEHAVIOR_SLEEP;
```

- 系统默认值是 `SLEEP`（息屏）
- 如果设为 `HOME`，按挂机键等于按 HOME 键，会发出 HOME intent
- 我们的 `NokiaDesktopActivity` 声明了 `HOME` category，理论上 HOME intent 会回到我们这里
- **但用户反馈即使设为默认桌面也不生效**，可能原因：
  - ROM 厂商修改了 `goHome()` 逻辑，写死了回到系统自带桌面
  - `END_BUTTON_BEHAVIOR` 实际是 `SLEEP` 而非 `HOME`
  - ROM 完全替换了 PhoneWindowManager 的 ENDCALL 处理

### 2.4 结论

| 方案 | 能否在 App 层实现 | 原因 |
|------|------------------|------|
| 重写 `dispatchKeyEvent` 拦截 ENDCALL | ❌ 不可能 | `PASS_TO_USER` 被清除，事件不到 App |
| 重写 `onKeyDown` / `onKeyUp` 拦截 ENDCALL | ❌ 不可能 | 同上 |
| 设置为默认桌面让 goHome 回到自己 | ⚠️ 不可靠 | 取决于 ROM 是否修改了 goHome 逻辑 |

**必须在系统拦截之上或之后想办法。**

## 3. 可选方案评估

### 3.1 方案 A：修改 `Settings.System.END_BUTTON_BEHAVIOR` 为 HOME

```java
Settings.System.putInt(getContentResolver(),
    Settings.System.END_BUTTON_BEHAVIOR,
    Settings.System.END_BUTTON_BEHAVIOR_HOME);
```

- 按挂机键 → 系统执行 `goHome()` → 发出 HOME intent → 回到 `NokiaDesktopActivity`
- **需要 `WRITE_SETTINGS` 权限**
- Android 4.4 可以写入此设置
- **风险**：ROM 可能写死了行为，修改设置不生效；`goHome()` 可能不回到我们的 Activity

**评估：可以尝试，但不能作为唯一手段。**

### 3.2 方案 B：AccessibilityService 监听焦点丢失 + 自动拉回（推荐）

#### 原理

AccessibilityService 运行在后台，可以监听系统级的窗口状态变化事件。
当挂机键导致焦点从 `NokiaDesktopActivity` 切走时（无论是 goHome 到别的桌面还是息屏后亮屏到别的应用），
AccessibilityService 会收到 `TYPE_WINDOW_STATE_CHANGED` 事件。
此时立即检测当前前台窗口是否是我们的 Activity，如果不是就启动 `NokiaDesktopActivity` 把自己拉回前台。

#### 兼容性

- AccessibilityService 在 Android 4.0（API 14）就已支持
- `performGlobalAction(GLOBAL_ACTION_HOME)` 在 API 16+ 可用
- Android 4.4（API 19）完全支持
- **不需要系统签名、不需要 root**

#### 实现细节

1. **新建 `NokiaKioskService extends AccessibilityService`**
   - 监听 `TYPE_WINDOW_STATE_CHANGED` 事件
   - 检测事件来源包名是否是本应用
   - 若不是本应用 → 当前前台已切走 → 启动 `NokiaDesktopActivity`
   - 使用 `Intent.FLAG_ACTIVITY_NEW_TASK | Intent.FLAG_ACTIVITY_REORDER_TO_FRONT`

2. **触发条件控制**
   - 在桌面设置中增加「防退出模式」开关（`SharedPreferences`）
   - 只有开关开启时才执行拉回逻辑
   - 默认关闭，用户按需开启

3. **避免无限循环**
   - 拉回操作本身也可能触发 `TYPE_WINDOW_STATE_CHANGED`
   - 使用 `Handler.postDelayed()` 加去抖（debounce），300ms 内不重复触发
   - 记录上次拉回时间，短时间内的重复事件忽略

4. **用户权限引导**
   - 首次开启「防退出模式」时，跳转到系统无障碍设置页
   - 引导用户手动开启 `NokiaKioskService`
   - 检测服务是否已启用：`AccessibilityManager.isAccessibilityServiceEnabled()`

#### 优点

- Android 4.4 完全支持，不需要系统签名
- 不需要修改 ROM
- 用户只需在「设置 → 无障碍」中开启服务
- 可通过开关控制，不影响正常使用

#### 缺点

- 不是真正"拦截"挂机键，而是"被切走后立即拉回"
- 用户可能看到一瞬间的画面闪烁（别的桌面闪一下再回来）
- 需要用户手动开启无障碍权限
- 如果挂机键行为是 SLEEP（息屏），则亮屏后才会触发拉回

### 3.3 方案 C：Lock Task Mode（不适用）

Android 5.0+ 的 Lock Task Mode 可以完全锁定在单个应用中，屏蔽所有物理按键。
**但这是 API 21+ 的功能，目标设备是 Android 4.4（API 19），不适用。**

### 3.4 方案 D：系统签名 + 修改 PhoneWindowManager（不适用）

直接修改 ROM 源码去掉 `result &= ~ACTION_PASS_TO_USER`，让事件传递到 App。
**需要 ROM 源码和系统签名，对当前项目不现实。**

### 3.5 方案 E：DeviceAdmin + KeyguardManager 组合（辅助方案）

利用已有的 `NokiaDeviceAdminReceiver`（`force-lock` 权限）：
- 监听 `ACTION_SCREEN_OFF`（挂机键导致息屏时）
- 在 `BroadcastReceiver` 中记录"非用户主动息屏"标记
- 监听 `ACTION_SCREEN_ON`，若标记存在则立即启动 `NokiaDesktopActivity`
- 配合方案 B 的 AccessibilityService 形成双重保障

**评估：作为方案 B 的补充手段，不是独立方案。**

## 4. 推荐方案：B + A 组合

### 4.1 总体架构

### 4.2 实施步骤

#### 步骤 1：新建 `NokiaKioskService.java`

路径：`app/src/main/java/ru/playsoftware/j2meloader/nokia/NokiaKioskService.java`

```java
package ru.playsoftware.j2meloader.nokia;

import android.accessibilityservice.AccessibilityService;
import android.accessibilityservice.AccessibilityServiceInfo;
import android.content.Intent;
import android.os.Handler;
import android.os.Looper;
import android.view.accessibility.AccessibilityEvent;

/**
 * 防退出守护服务（AccessibilityService）。
 *
 * 当挂机键（ENDCALL）被系统拦截导致焦点从 NokiaDesktopActivity 切走时，
 * 本服务检测到窗口状态变化，自动将 NokiaDesktopActivity 拉回前台。
 *
 * 仅在用户于「桌面设置 → 防退出模式」中开启后生效。
 * 需要用户在「系统设置 → 无障碍」中手动启用本服务。
 */
public class NokiaKioskService extends AccessibilityService {

    private static final String TAG = "KioskService";
    private static final long PULL_BACK_DEBOUNCE_MS = 300;
    private static final String TARGET_ACTIVITY = NokiaDesktopActivity.class.getName();

    private final Handler handler = new Handler(Looper.getMainLooper());
    private long lastPullBackTime = 0;

    @Override
    protected void onServiceConnected() {
        super.onServiceConnected();
        NokiaLog.i(TAG, "防退出守护服务已连接");

        // 通过代码配置 AccessibilityServiceInfo（兼容 4.4，不依赖 meta-data XML）
        AccessibilityServiceInfo info = new AccessibilityServiceInfo();
        // 监听窗口状态变化（窗口切换、Activity 启动等）
        info.eventTypes = AccessibilityEvent.TYPE_WINDOW_STATE_CHANGED;
        // 只监听窗口状态变化的反馈
        info.feedbackType = AccessibilityServiceInfo.FEEDBACK_GENERIC;
        // 不需要延迟通知
        info.notificationTimeout = 0;
        setServiceInfo(info);
    }

    @Override
    public void onAccessibilityEvent(AccessibilityEvent event) {
        if (event == null) return;

        // 检查防退出模式是否开启
        if (!isKioskModeEnabled()) {
            return;
        }

        int eventType = event.getEventType();
        if (eventType != AccessibilityEvent.TYPE_WINDOW_STATE_CHANGED) {
            return;
        }

        // 获取事件来源包名
        String packageName = null;
        if (event.getPackageName() != null) {
            packageName = event.getPackageName().toString();
        }

        // 如果事件来自本应用，不需要处理
        String ownPkg = getPackageName();
        if (ownPkg.equals(packageName)) {
            return;
        }

        NokiaLog.i(TAG, "检测到焦点切走，来源包名=" + packageName
                + "，执行拉回");

        // 去抖：避免短时间内重复拉回
        long now = System.currentTimeMillis();
        if (now - lastPullBackTime < PULL_BACK_DEBOUNCE_MS) {
            NokiaLog.d(TAG, "去抖：距上次拉回不足 " + PULL_BACK_DEBOUNCE_MS + "ms，跳过");
            return;
        }
        lastPullBackTime = now;

        // 拉回 NokiaDesktopActivity
        pullBackToDesktop();
    }

    @Override
    public void onInterrupt() {
        NokiaLog.w(TAG, "防退出守护服务被中断");
    }

    /** 将 NokiaDesktopActivity 拉回前台 */
    private void pullBackToDesktop() {
        try {
            Intent intent = new Intent(this, NokiaDesktopActivity.class);
            intent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK
                    | Intent.FLAG_ACTIVITY_REORDER_TO_FRONT
                    | Intent.FLAG_ACTIVITY_SINGLE_TOP);
            startActivity(intent);
            NokiaLog.i(TAG, "已启动 NokiaDesktopActivity 拉回前台");
        } catch (Exception e) {
            NokiaLog.e(TAG, "拉回 NokiaDesktopActivity 失败", e);
        }
    }

    /** 检查防退出模式是否开启（从 SharedPreferences 读取） */
    private boolean isKioskModeEnabled() {
        return getSharedPreferences(NokiaSettingsStorage.PREFS_NAME, MODE_PRIVATE)
                .getBoolean("kiosk_mode_enabled", false);
    }
}
```

#### 步骤 6：方案 A — 尝试修改 END_BUTTON_BEHAVIOR

在开启防退出模式时，尝试将挂机键行为改为 HOME：

```java
/**

 * 需要 WRITE_SETTINGS 权限。某些 ROM 可能不允许修改或写死了行为。

private void trySetEndButtonBehaviorHome() {
    try {
        Settings.System.putInt(getContentResolver(),
                Settings.System.END_BUTTON_BEHAVIOR,
                Settings.System.END_BUTTON_BEHAVIOR_HOME);
        NokiaLog.i("Kiosk", "END_BUTTON_BEHAVIOR 已设为 HOME");
    } catch (Exception e) {
        NokiaLog.w("Kiosk", "无法修改 END_BUTTON_BEHAVIOR", e);
    }
}
```

#### 步骤 7：检测无障碍服务是否已启用

```java
/**
 * 检查 NokiaKioskService 是否已在系统无障碍设置中启用。
 */
public static boolean isKioskServiceEnabled(Context context) {
    String serviceName = context.getPackageName() + "/"
            + NokiaKioskService.class.getName();
    String enabledServices = Settings.Secure.getString(
            context.getContentResolver(),
            Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES);
    if (enabledServices == null) return false;
    return enabledServices.contains(serviceName);
}

/**
 * 跳转到系统无障碍设置页，引导用户启用服务。
 */
public static void openAccessibilitySettings(Context context) {
    Intent intent = new Intent(Settings.ACTION_ACCESSIBILITY_SETTINGS);
    if (!(context instanceof Activity)) {
        intent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK);
    }
    context.startActivity(intent);
}
```

## 5. 风险与注意事项

### 5.1 用户体验

- **方案 B 是"事后拉回"而非"事前拦截"**，用户可能看到极短暂的画面闪烁（别的桌面闪一下再回来）
- 在性能较低的 240×320 设备上，闪烁可能更明显
- 可以通过在 `NokiaDesktopActivity.onPause()` 中保持窗口快照来减轻视觉闪烁（可选优化）

### 5.2 无障碍权限依赖

- AccessibilityService 必须由用户手动在系统设置中开启，不能自动开启
- 用户可能不理解为什么要开无障碍权限，需要在 UI 中做好引导说明
- 用户可能在之后误关闭无障碍服务，需要在桌面设置中显示当前服务状态

### 5.3 去抖与循环触发

- 拉回操作本身会触发 `TYPE_WINDOW_STATE_CHANGED`，必须去抖避免无限循环
- 使用 300ms 去抖 + 包名检测（事件来自本应用则忽略）双重保护

### 5.4 ROM 兼容性

- 方案 A（修改 `END_BUTTON_BEHAVIOR`）在部分 ROM 上可能不生效
- 方案 B（AccessibilityService）在极少数深度定制的 ROM 上可能被限制
- 建议在目标设备 `4a24ecf`（Android 4.4, 240×320）上实测验证

### 5.5 对现有功能的影响

- 防退出模式默认关闭，不影响现有功能
- 仅在用户主动开启后才生效
- 开启后只影响桌面主页，不影响功能表、设置等子页面（因为子页面也在 `NokiaDesktopActivity` 内）

### 5.6 电量影响

- AccessibilityService 只监听 `TYPE_WINDOW_STATE_CHANGED`，不监听其他事件
- 正常使用时事件频率很低（仅在窗口切换时触发）
- 电量影响可忽略

## 7. 测试计划

1. **在 4a24ecf 设备（Android 4.4, 240×320）上测试**：
   - 开启防退出模式 → 开启无障碍服务 → 按挂机键 → 验证是否回到桌面
   - 关闭防退出模式 → 按挂机键 → 验证恢复正常行为
   - 在功能表页面按挂机键 → 验证是否回到桌面（而非退出）
   - 在桌面设置页面按挂机键 → 验证是否回到桌面

2. **测试方案 A 是否生效**：
   - 开启防退出模式后，检查 `Settings.System.END_BUTTON_BEHAVIOR` 的值
   - 若为 HOME → 方案 A 在此设备上生效
   - 若仍为 SLEEP → 方案 A 不生效，依赖方案 B

3. **测试方案 B 的响应速度**：
   - 按挂机键后计时，测量从切走到拉回的耗时
   - 评估画面闪烁程度是否可接受

4. **长时间稳定性测试**：
   - 连续按挂机键 20 次，验证不会出现服务崩溃或无限循环
