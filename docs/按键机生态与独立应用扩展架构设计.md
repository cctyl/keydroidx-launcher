# 按键机生态与独立应用扩展架构设计文档

## 一、背景与设计目标

### 1.1 现状与痛点
在 Android 按键机（物理全键盘/T9 键盘设备）生态中，开发适配按键操作的应用面临以下核心挑战：
1. **物理键值高度碎片化**：不同品牌、不同型号的按键机，其确认键、左右软键、返回键甚至方向键的物理 KeyCode 差异巨大（例如部分机型确认键为 `KEYCODE_DPAD_CENTER(23)`，部分为 `KEYCODE_ENTER(66)` 或 `KEYCODE_MENU(82)`）。若每个应用都需要用户独立配置一次按键，交互极其繁琐。
2. **桌面集成（Monolith）的局限性**：
   - **工程臃肿与编译成本**：当前原键桌面（Launcher）集成了 J2ME-Loader 模拟器、C++ NDK 3D 渲染引擎、dxlib 工具链等复杂底层代码。若将音乐播放器、浏览器、文件管理器等全部塞入桌面工程，会导致主工程极其庞大，日常维护与构建调试成本成倍增加。
   - **系统常驻与内存稳定性**：桌面（Launcher）是系统常驻的 HOME 宿主。如果内置多媒体解码或复杂 WebView 渲染，一旦发生内存泄漏（OOM）或原生层崩溃，会导致整个桌面崩溃重启，严重破坏用户体验。
   - **阻碍社区协同开发**：外部开发者如果想贡献一个简单的按键机音乐播放器，需要克隆几十 MB 包含 NDK/C++ 的主仓库并配置繁琐的 NDK 工具链，门槛极高。

### 1.2 架构目标
- **Launcher 作为按键与服务中枢**：原键桌面负责统一管理物理按键映射、状态栏信息与桌面组件容器，并通过标准 IPC（ContentProvider）将按键配置安全共享给外部应用。
- **独立轻量 APK 矩阵**：音乐播放器、专用浏览器、记事本等作为独立 APK 存在，独立编译、独立进程、崩溃隔离。
- **即插即用，无感同步**：独立应用启动时自动从桌面读取按键配置，用户只需在桌面配一次按键，所有生态应用全自动适配。
- **极致轻量的开源接入方案**：提供极简的按键机应用开发模板（SDK/基类），外部开发者只需关注纯 Java/Kotlin 业务逻辑，5 分钟即可开发出完全适配按键机操作的复古应用。

## 三、通信协议与数据契约设计

### 3.1 按键共享契约（`NokiaKeyProvider`）

桌面端对外暴露只读 `ContentProvider`，独立应用通过标准 `ContentResolver` 查询当前设备的按键映射。

- **Provider Authority**：`ru.playsoftware.j2meloader.nokia.keyprovider`（Debug 变体为 `io.github.cctyl.nokia.debug.keyprovider`）
- **查询 URI**：`content://<AUTHORITY>/keys`
- **数据表结构（Cursor Schema）**：
  | 字段名 (`Column`) | 类型 (`Type`) | 说明 | 示例值 |
  | :--- | :--- | :--- | :--- |
  | `action_name` | `TEXT` | 语义动作标识符 | `UP`, `DOWN`, `LEFT`, `RIGHT`, `SELECT`, `SOFT_LEFT`, `SOFT_RIGHT`, `CALL`, `BACK` |
  | `action_code` | `INTEGER` | 语义动作枚举常量值 | `0 (UP)`, `1 (DOWN)`, `4 (SELECT)` 等 |
  | `key_code` | `INTEGER` | 该动作绑定的物理 KeyEvent KeyCode | `19 (DPAD_UP)`, `23 (DPAD_CENTER)` 等 |

#### 桌面端实现要点（轻量化）：
```java
public class NokiaKeyProvider extends ContentProvider {
    public static final String AUTHORITY_RELEASE = "ru.playsoftware.j2meloader.nokia.keyprovider";
    public static final String AUTHORITY_DEBUG = "io.github.cctyl.nokia.debug.keyprovider";

    @Override
    public Cursor query(@NonNull Uri uri, String[] projection, String selection, String[] selectionArgs, String sortOrder) {
        MatrixCursor cursor = new MatrixCursor(new String[]{"action_name", "action_code", "key_code"});
        NokiaKeyBinding binding = NokiaKeyBinding.getInstance(getContext());
        
        cursor.addRow(new Object[]{"UP", NokiaKeyBinding.ACTION_UP, binding.getKeyCode(NokiaKeyBinding.ACTION_UP)});
        cursor.addRow(new Object[]{"DOWN", NokiaKeyBinding.ACTION_DOWN, binding.getKeyCode(NokiaKeyBinding.ACTION_DOWN)});
        cursor.addRow(new Object[]{"LEFT", NokiaKeyBinding.ACTION_LEFT, binding.getKeyCode(NokiaKeyBinding.ACTION_LEFT)});
        cursor.addRow(new Object[]{"RIGHT", NokiaKeyBinding.ACTION_RIGHT, binding.getKeyCode(NokiaKeyBinding.ACTION_RIGHT)});
        cursor.addRow(new Object[]{"SELECT", NokiaKeyBinding.ACTION_SELECT, binding.getKeyCode(NokiaKeyBinding.ACTION_SELECT)});
        cursor.addRow(new Object[]{"SOFT_LEFT", NokiaKeyBinding.ACTION_SOFT_LEFT, binding.getKeyCode(NokiaKeyBinding.ACTION_SOFT_LEFT)});
        cursor.addRow(new Object[]{"SOFT_RIGHT", NokiaKeyBinding.ACTION_SOFT_RIGHT, binding.getKeyCode(NokiaKeyBinding.ACTION_SOFT_RIGHT)});
        return cursor;
    }
}
```

#### 独立应用端读取与降级保护（Client 读取）：
```java
public class NokiaKeyClient {
    // 优先读取 Release Authority，失败则尝试 Debug Authority，均失败则使用默认按键
    public static Map<Integer, Integer> loadDesktopKeys(Context context) {
        Map<Integer, Integer> actionToKeyMap = new HashMap<>();
        if (!tryQueryProvider(context, "ru.playsoftware.j2meloader.nokia.keyprovider", actionToKeyMap)) {
            tryQueryProvider(context, "io.github.cctyl.nokia.debug.keyprovider", actionToKeyMap);
        }
        if (actionToKeyMap.isEmpty()) {
            fillDefaultFallbackKeys(actionToKeyMap);
        }
        return actionToKeyMap;
    }
}
```

### 3.2 跨应用状态联动协议（以音乐播放器为例）

独立音乐播放器在后台播放时，通过隐式/显式广播向桌面发送元数据，桌面上的「音乐小组件」实现即时显示与交互控制。

#### 广播 Action 定义：
1. **播放器状态通知桌面**：`ru.playsoftware.j2meloader.nokia.action.MUSIC_STATUS_CHANGED`
   - `extra_is_playing` (`boolean`)：当前是否在播放中
   - `extra_title` (`String`)：歌曲名
   - `extra_artist` (`String`)：歌手名
   - `extra_duration` (`long`)：总时长（毫秒）
   - `extra_position` (`long`)：当前播放进度（毫秒）
2. **桌面控制播放器**：`ru.playsoftware.j2meloader.nokia.action.MUSIC_CONTROL`
   - `extra_command` (`String`)：`TOGGLE_PLAY`, `PREV`, `NEXT`, `STOP`

## 四、独立应用开发 SDK 与脚手架规划

为方便社区开发者快速开发符合按键机规范的应用，规划抽象出一套极其轻量的 SDK（`nokia-keyphone-sdk`）：

### 4.1 SDK 核心组件清单
1. **`NokiaKeyResolver`**：
   - 自动在 Activity 的 `dispatchKeyEvent` 中进行物理按键解析；
   - 严格遵循 `ACTION_DOWN` 与 `ACTION_UP` 状态配对消费机制，杜绝按键粘连与重复触发。
2. **`NokiaScaledActivity`（UI 缩放与基准容器）**：
   - 内置以 `240dp` 宽度为基准的等比自适应缩放引擎（移植自 `NokiaBaseActivity`）；
   - 顶部提供标准诺基亚 S40/S60 标题栏，底部提供标准三栏式软键栏（左软键 / 确认 / 右软键）。
3. **`NokiaListPageActivity` 与 `NokiaScrollPageActivity`**：
   - **列表型页面**：开箱即用的循环焦点导航（顶部按「上」跳到末尾，底部按「下」跳到开头）；
   - **图文/富文本页面**：开箱即用的平滑翻页能力，动态步长计算（单次翻滚 45% 视口高度），屏蔽内部 Text 获焦干扰。

### 4.2 独立应用开发模板工程（Template Repo）
在 GitHub 上建立 `retro-keyphone-template` 开源脚手架：
- 预置好 Gradle 依赖与 proguard 配置；
- 包含一个已经跑通的 HelloWorld 单页面（方向键选择条目 + 左右软键弹窗）；
- 开发者只需克隆仓库，直接在 `onItemClick` 中编写业务逻辑即可。

## 五、生态应用孵化与开发路线

### 第一阶段（基础设施建设 - 预计 1~2 天）：
- [ ] 在当前原键桌面项目中实现 `NokiaKeyProvider`，暴露当前配置的按键映射；
- [ ] 允许外部应用安全查询按键数据（配置 `exported="true"`）；
- [ ] 编写简单的单元测试与 adb provider 查询验证脚本。

### 第二阶段（官方参考实现：按键音乐播放器 - 预计 3~5 天）：
- [ ] 创建全新轻量独立仓库 `Nokia-Retro-Music`；
- [ ] 基于 `MediaPlayer` / `ExoPlayer` 实现后台播放 Service；
- [ ] 设计诺基亚复古 S40 音乐播放界面（像素风格进度条、歌曲列表、音效均衡器 UI）；

- [ ] 实现与桌面的音乐组件广播联动。

### 第三阶段（官方参考实现：按键轻量浏览器 - 预计 3~5 天）：

### 第四阶段（开源发布与社区文档）：

- [ ] 开放脚手架模板，引导社区开发者贡献更多独立生态应用（如记事本、文件管理器、FM收音机、离线小说阅读器等）。

## 六、总结
本方案采用「**Launcher 作为按键与服务中枢 + 独立轻量生态 APK 矩阵**」的架构模式，完美平衡了**系统稳定性**、**开发轻量性**与**开源生态可扩展性**。通过标准的 `ContentProvider` 机制，以不到 100 行的核心代码即可彻底解决跨应用按键映射共享的行业难题，为后续按键机生态的繁荣奠定了坚实的基础。
