# 桌面「正在播放」音乐组件设计文档

> 功能：在 KeydroidX 桌面组件区新增「正在播放」组件，跨进程实时显示音乐播放器的当前歌曲、歌手、当前歌词行与播放进度；按确认键/点击进入音乐播放详情页。
>
> 关联仓库：
> - 本仓库（桌面侧）：`keydroidx-launcher`
> - 音乐播放器（数据源侧）：`keydroidx-music`，其 `docs/WIDGET_DESIGN.md` 为该功能的完整双端设计文档

---

## 1. 功能定位与架构

桌面组件区只渲染**原生组件**（`NokiaWidgetItem` 行布局），**不接入 `AppWidgetHost`**。播放状态有两条读取通道，按优先级取用：

1. **MediaSession（首选）**——系统「正在播放」的标准做法，只读 system_server 维护的 session 表；
2. **ContentProvider（回退）**——音乐 App 导出的 `content://...playback/state`，能拿到歌词（MediaSession metadata 里没有）。

第 3 条不是通道，而是**已知结论**：若音乐是被桌面自己的后台管理杀掉的，那它必然没在播放，一行代码都不用查（详见 §2）。

```
                    ┌── ① MediaSession（getActiveSessions，不拉起对方进程）
[桌面] 音乐组件行 ◄──┤── ② ContentProvider query（仅当确认对方进程存活时）
                    └── ③ 「我杀的」→ 直接未播放（零跨进程调用）

[音乐App] PlaybackStateManager(StateFlow)
   │  广播 ACTION_PLAYBACK_CHANGED + contentResolver.notifyChange(PLAYBACK_URI)
   ▼
[音乐App] PlaybackProvider (content://io.github.cctyl.keydroidx.music.playback/state)
   ▲
   │ ContentObserver 监听（仅对方存活时注册）
[桌面] NokiaDesktopFragment.refreshMusicAsync()
   │ 确认键/点击
   ▼
[音乐App] MusicPlayerActivity（黑胶唱机详情页）
```

> **设计红线：任何情况下都不能为了渲染组件行而把音乐进程冷启动起来。**
> ContentProvider 的 `query()` / `registerContentObserver()` 在对方进程不在时会让 AMS 把它冷启动，
> 调用线程同步等待——这是「清理后台 → 返回桌面」卡顿 1.2s 的根因，详见 §2.1。

---

## 2. 读取通道与冷启动规避

### 2.1 问题背景（实测）

从后台管理「清除全部」后按右软键返回桌面，主线程被阻塞约 1.2s：

```
10:15:00.258 ActivityManager: asking zygote to start proc
10:15:01.475 ContentProviderHelper: publishContentProviders
10:15:01.492 Desktop: 组件区已渲染 6 个组件      ← 主线程阻塞 1.27s
10:15:01.506 Choreographer: Skipped 75 frames!
10:15:01.555 OpenGLRenderer: Davey! duration=1303ms
```

根因：组件行渲染时同步 `query(MUSIC_PLAYBACK_URI)`，而音乐刚被清理掉，AMS 现场把它冷启动。
用户刚清完后台、桌面转头又把应用拉起来——既自相矛盾又卡顿。

### 2.2 三级策略

| 优先级 | 条件 | 行为 | 是否会冷启动对方进程 |
|--------|------|------|--------------------|
| ① | 后台管理刚清理过音乐（`wasCleared`） | 主线程立即刷成「未播放」；后台用 `ps -A` 确认是否已复活，仍死则直接返回，不查 Provider | 否 |
| ② | MediaSession 通道可用且读到数据 | 取歌名/歌手/进度；正在播放时才补一次 Provider 查歌词（此时进程必然存活） | 否 |
| ③ | 以上都不成立 | 先用 `isPackageAlive()` 判活（5.0+ `ps -A`，4.4 `getRunningAppProcesses`），**存活才 query**，已死直接返回未播放 | 否 |
| — | 无法判活（如 5.0+ 未激活 mini_shizuku） | 按「存活」处理，回退 Provider 查询（仍在后台线程，主线程不卡） | 会（但属不可区分场景） |

判断存活与清理后台用的是同一个能力（mini_shizuku 的 `ps -A`），权限天然对称：
**能杀掉它，就能在不拉起它的前提下确认它是否还活着。**

### 2.3 「我杀死了 music」——桌面自己的因果知识

`NokiaBgManagerHelper` 维护一份进程内「被杀名单」：

- `clearBackgroundTasks()` 在 `am force-stop` / `killBackgroundProcesses` 成功时调 `markCleared(pkg)`；
- `wasCleared(pkg)` / `unmarkCleared(pkg)` / `isPackageAlive(ctx, pkg)` 对外暴露结论；
- 桌面据此**跳过一切跨进程查询**，并跳过 `registerContentObserver`（注册本身同样会冷启动对方进程）；
- 后台线程检测到对方复活（`ps -A` 里又出现）时 `unmarkCleared` 并补注册观察者——原观察者已随对方进程失效。

修复后实测（清理后台 → 返回桌面）：

```
23.165 Desktop : 组件区已渲染 6 个组件
23.264 Desktop : 音乐进程未运行，跳过播放状态查询（避免冷启动）
23.267 Desktop : 已注册音乐播放状态 ContentObserver
23.270 Desktop : 音乐播放组件行已刷新
（无 asking zygote / Start proc / Skipped frames / Davey；ps -A 无音乐进程）
```

## 2. 数据接口（音乐 App 侧，只读）

**Provider URI**：`content://io.github.cctyl.keydroidx.music.playback/state`

| 列名 | 类型 | 说明 |
|------|------|------|
| `song_id` | Long | 歌曲 ID |
| `title` | String | 歌曲标题 |
| `artist` | String | 歌手名 |
| `album_art_uri` | String | 专辑封面 URL |
| `is_playing` | Int | 0/1 是否正在播放 |
| `position_ms` | Long | 当前播放位置 (ms) |
| `duration_ms` | Long | 歌曲总时长 (ms) |
| `lyric_text` | String | 当前歌词行文本（无歌词为空） |
| `updated_at` | Long | 数据更新时间戳 (ms) |

**变更通知**：音乐 App 播放状态变化时 `notifyChange(PLAYBACK_URI)`，桌面侧 `ContentObserver` 收到回调即刷新。

> 注意：`MediaSession` 的 metadata 只含 title/artist/albumTitle（见音乐 App `PlaybackService.buildMediaItem()`），
> **不含歌词**。歌词只能走 Provider，因此只在「正在播放」时补查——此时对方进程必然存活（有前台服务），查询是毫秒级。

## 3. 桌面侧实现

### 3.1 新增组件类型 `TYPE_MUSIC_PLAYER = 11`

文件：`app/src/main/java/ru/playsoftware/j2meloader/nokia/NokiaWidgetItem.java`

```java
public static final int TYPE_MUSIC_PLAYER = 11; // 正在播放（音乐播放器状态，不可编辑）
public static final int TYPE_COUNT = 12;
```

新增元数据：
- `getTypeName(11)` → `"正在播放"`
- `getDefaultLabel(11)` → `"正在播放"`
- `getTypeTag(11)` → `"[音乐]"`
- `getTypeIconUnicode(11)` → `NokiaIcons.ICON_MUSIC_NOTE`
- `getTypeIcon(11)` → `R.drawable.ic_nokia_music`
- `isEditable()` → `false`（不可编辑）

### 3.2 图标

- `NokiaIcons.java` 新增 `ICON_MUSIC_NOTE = "\ue405"`（Material Icons 音符）
- 新增矢量图标 `app/src/main/res/drawable/ic_nokia_music.xml`（白色音符）

### 3.3 组件行渲染

文件：`app/src/main/java/ru/playsoftware/j2meloader/nokia/NokiaDesktopFragment.java`

`createWidgetRow()` 新增分支，委托 `createMusicPlayerWidgetRow(item)` 创建行：

布局结构（横向）：
```
[♫音符图标] [文本列: 歌名-歌手] [进度条]
            [文本列: 当前歌词行]
```

- **第一行**：歌名 - 歌手，若未播放追加 `[暂停]`；无歌曲显示 `"音乐播放器（未播放）"`
- **第二行**：当前歌词行，无歌词显示 `"暂无歌词"`
- **进度条**：`position_ms / duration_ms`，横条填充

**三个取数方法不再各自发起跨进程查询**，改为共享一份快照：

```java
private static final class MusicSnapshot {
    String title = "音乐播放器（未播放）";   // 默认值即「未播放」态，无需任何查询
    String lyric = "暂无歌词";
    float progress;
    boolean playing;
}
```

- `getMusicSnapshot()`：**只返回缓存或默认值，绝不发起 IPC**——「未播放」是默认值，本来就不需要查询；
- `refreshMusicAsync()`：把取数整体挪到 `MUSIC_EXECUTOR`（单线程串行，避免 register 与 refresh 竞态）；
- 结果回到主线程后 `musicSnapshot = s` + `rebuildMusicWidgetRowOnly()` 局部刷新；
- `musicRefreshSeq` 序号保护：只应用最后一次刷新的结果，避免乱序覆盖；
- `resetWidgetDataSnapshot()` 不清 `musicSnapshot`——清掉会让每次重建组件区都先闪回「未播放」。

### 3.4 实时刷新

- **ContentObserver**：音乐存活时注册，收到 `onChange` 后调 `refreshMusicAsync()`（不再直接重建行，统一走快照）；
  注册与注销同样在 `MUSIC_EXECUTOR` 上执行（注册会等 Provider 连接，对方不在时同样阻塞）；
  音乐被后台管理清理时**跳过注册**，等检测到复活后再补。
- **MediaSession**：`NokiaMusicSessionReader` 读取，需「通知使用权」，见 §3.8。
- `rebuildMusicWidgetRowOnly()`：**仅重建音乐组件行**（`removeViewAt` + `addView` 原位替换），并同步更新 `focusTargets` 对应索引，**保持焦点不丢失**、其余组件不动。

### 3.5 确认键 / 点击行为

`setupWidgetRowClick()` 新增 `TYPE_MUSIC_PLAYER` 分支 → `launchMusicPlayer()`：

```java
Intent intent = new Intent(Intent.ACTION_MAIN);
intent.setClassName("io.github.cctyl.keydroidx.music",
        "io.github.cctyl.keydroidx.music.ui.MusicPlayerActivity");
intent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK);
startActivity(intent);
```

音乐 App 未安装时捕获异常并 Toast 提示。

### 3.6 类型选择页

文件：`app/src/main/java/ru/playsoftware/j2meloader/nokia/NokiaWidgetTypePickerFragment.java`

`TYPE_IDS` 数组追加 `NokiaWidgetItem.TYPE_MUSIC_PLAYER`。`onTypeSelected()` 落入默认分支（直接添加并返回 S1），无需额外跳转。

### 3.7 包可见性

`app/src/main/AndroidManifest.xml` `<queries>` 新增：

```xml
<package android:name="io.github.cctyl.keydroidx.music" />
```

> 音乐 App 的 `MusicPlayerActivity` 已设为 `android:exported="true"`，桌面侧才能通过显式 Intent 跨进程启动。

### 3.8 通知使用权（MediaSession 的前提）

MediaSession 通道要求本 App 被授予**通知使用权**（`NotificationListenerService`），
因此新增一个空壳服务只为换取该权限：

```java
public class NokiaNotificationListenerService extends NotificationListenerService {}
```

```xml
<service
    android:name=".nokia.NokiaNotificationListenerService"
    android:exported="true"
    android:permission="android.permission.BIND_NOTIFICATION_LISTENER_SERVICE">
    <intent-filter>
        <action android:name="android.service.notification.NotificationListenerService" />
    </intent-filter>
</service>
```

授权状态判定：读 `Settings.Secure "enabled_notification_listeners"` 匹配自身包名（无官方 API 可查自身）。

**主动提示弹窗（必需）**：这属于要用户授权的系统权限，不能默默退化到会冷启动音乐的 Provider 查询。
`NokiaMusicSessionReader.showGrantPrompt(fm, ctx, neverAsk)` 复用通用选项弹窗
（`NokiaOptionsDialog`），标题「音乐组件需要通知使用权」，选项：

| 选项 | 行为 |
|------|------|
| 去开启 | 跳 `Settings.ACTION_NOTIFICATION_LISTENER_SETTINGS` |
| 以后再说 | 仅关闭 |
| 不再提示 | 写入 `NokiaSettingsStorage`，永久不再提示（桌面与高级设置共用） |

触发点：

- `NokiaDesktopFragment.maybePromptNotificationAccess()` —— `onResume` 时若存在音乐组件、
  未授予、用户未选「不再提示」且本进程未弹过，则弹一次；
- `NokiaAdvancedSettingsFragment` 第 3 项「通知使用权」——点击先弹同一弹窗（已授予则 Toast 提示），
  行尾实时显示「已授予 / 未授予」，从系统设置页返回后自动刷新。

## 5. 交互流程

```
桌面待机屏 → UP/DOWN 移到「正在播放」行
  → 行高亮（青色背景+白字加粗），显示：
      ♫ 顺风顺水 - 邹念慈/繁星合唱团
      ♪ 风起的时候 谁在等候     ← 后台实时歌词
      ━━━━━━━━━━━━━━            ← 进度条
  → 按确认键 → 打开 MusicPlayerActivity
  → 右软键返回桌面，焦点回到该行
```

## 6. 兼容性与降级

| 场景 | 行为 |
|------|------|
| 音乐 App 未安装 | 组件点击 Toast「未安装音乐播放器」 |
| 已安装但未播放 | 显示「音乐播放器（未播放）」 |
| 音乐 App 进程未运行 | 不发起任何跨进程调用，直接显示「未播放」 |
| 音乐被桌面后台管理清理 | 同上（已知结论，无需查询）；复活后自动恢复读取并补注册观察者 |
| 未授予通知使用权 | 回退 Provider 通道（后台线程，先判活）；并主动弹窗引导授权 |
| API < 21 | MediaSession 不可用，走 Provider 通道；判活改用 `getRunningAppProcesses()` |
| 无法判活（5.0+ 未激活 mini_shizuku） | 按存活处理，回退 Provider 查询 |
| 无歌词 | 显示「暂无歌词」 |
| 播放暂停 | 标题行追加 `[暂停]` |
