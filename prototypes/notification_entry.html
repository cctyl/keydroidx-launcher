推荐方案：三层入口

层级入口路径成本结论
主入口桌面通知条 桌面 → 方向键移到通知条 → 确认键 中（新 view + 接入 focusTargets） 推荐
兜底功能表格子 左软键 → 功能表 → 通知中心 低（NokiaMenuFragment:613 后加一项） 推荐，先做这个
进阶按键直达 任意界面按绑定的键 高（NokiaKeyBinding 6 处并行结构） 后续
不推荐顶部快捷栏 快捷栏加「通知」图标 低，但挤占用户自定义快捷栏 否
不推荐桌面设置子项 右软键 → 系统与权限 → 通知中心 层级太深，与「快捷」目标相反 否（仅放授权/开关）

为什么主入口是「桌面通知条」

1. 通知条只在有通知时出现，无通知不占桌面空间 —— 不破坏现有桌面布局；
2. 它本身就是信息展示（未读数 + 最新一条摘要），用户不进页面也能看到关键内容；
3. 复用现有焦点体系：作为第 2 个焦点区插入 focusTargets（快捷栏 → 通知条 → 组件 → 快捷开关），方向键即可到达，确认键进入；
4. 桌面按 Home 键就到，路径最短：Home → ↓ → 确认，真正免下拉。

按键语义（桌面页，通知条聚焦时）

↑/↓：跨区移动焦点（快捷栏 ⇄ 通知条 ⇄ 组件 ⇄ 快捷开关）
确认键：进入通知中心，并自动定位到最新一条
左软键：功能表（保持不变，不抢软键）
右软键：桌面设置（保持不变）
长按确认键（可选）：直接全部清除，二次确认后执行

落地落点（已确认的代码位置）

主入口：fragment_nokia_desktop.xml 快捷栏下方新增通知条；NokiaDesktopFragment.collectWidgetTargets()（:1949）与 onDirection()（:1963）加一个焦点区；确认进入走 NokiaDesktopActivity.openFragment()（:659）
兜底入口：NokiaMenuFragment.java:613 后追加 TYPE_NOTIFICATION 项 + NokiaAppItem 新常量，格子可带未读角标
数据层：NokiaNotificationListenerService.java:17 已有空壳 + Manifest 已注册 + 授权弹窗已就绪（NokiaDesktopFragment.java:1155），只需补 getActiveNotifications()
设置位：桌面设置 → 系统与权限 加「通知中心」（开关 + 授权引导）

原型操作
